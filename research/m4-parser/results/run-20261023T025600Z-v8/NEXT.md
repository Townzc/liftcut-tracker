# After v8: CPU work before another GPU notice

This is a post-result design draft, **not a frozen or GPU-ready v9 protocol**.
V8 is complete and rejected; its instance is OFF. No additional GPU run, native
activation or private continuous acceptance is authorized by this completed
window. The private 20 originals and all derivatives remain excluded from
training, diagnostics, examples and augmentation.

## What is now known

- Full-contract training and inference together recover output validity and
  useful challenge records. Either prompt substitution alone is harmful here.
  Weight/tokenizer/system compatibility needs an explicit artifact contract.
- The dominant unresolved boundary is RPE set scope (15/15 failures), followed
  by missing-unit inputs becoming unweighted records (4) and dumbbell/barbell
  identity confusion (5). Four illegal reason strings also remain.
- These are observed residual behaviors, not demonstrated optimization causes.
  More prompt text is not an evidence-backed universal fix. The current maximum
  training length is already 511/512 tokens; adding text risks truncation.
- The strict reason gate prevents a wrong legal reason from being counted as a
  successful clarification. Source guards prevent writes but do not establish
  useful incremental coverage; the source-only baseline still matters.

## Bounded CPU preparation

1. Audit only the existing training corpus and its provenance: compare explicit
   scope, absent scope, missing units versus bodyweight, reason-token coverage and
   action identity exposure. Separate label contradictions from sparse phrasing.
   Use the v2/v8 saved history for diagnosis, never copy challenge failures into
   training or rewrite the private 20 into templates.
2. Freeze a single training-side intervention only after that audit supports it.
   Keep the full v8 inference contract and cached D control fixed to avoid
   re-confounding train/inference prompts. Specify any changed sample weights or
   synthetic training templates before new outcomes; do not quietly change both.
   If evidence instead calls for a different intervention, record the design
   change and its rationale before a new run. No candidate selection from v8 arms.
3. Bind training/inference system hashes, tokenizer IDs, loss masks and weight
   lineage in a compatibility manifest. Test rejection of mismatched artifacts.
   Audit every sequence against the token limit without dropping examples or
   truncating labels; rehearse real CPU optimization/export and complete recovery.
4. Preserve original raw/strict/guarded/useful gates. Constraint decoding, if later
   studied, needs its own separate comparison: it can constrain reason spelling
   but cannot establish correct scope or identity. Do not repair raw outputs or
   treat a guard-only pass as a candidate pass.
5. Freeze the bounded runner, source and analysis plan, pass all CI, and restore
   the exact source package before notifying a fresh GPU opening. Keep semantic
   rejection ahead of optional quantization, followed by backup verification/OFF.

After a development pass, run the original continuous acceptance with actual
candidate outputs, including confirmed-record targeting, corrections, inherited
loads and undo/re-do. Then validate useful coverage, native integration and real
devices before activation. Existing UI and confirmation/write paths stay intact.
