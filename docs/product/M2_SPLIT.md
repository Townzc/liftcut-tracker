# M2 拆分清单：App 内 Agent

依据：[方案](2026-10-18-mobile-agent-plan.md)第 4 节 M2、第 6 节规则；[展品方案](2026-10-13-showcase-plan.md)第 2 节。每项一个分支一个 PR，有效改动约 400 行以内，按顺序做；带“界面”的项跑 Playwright 并截手机宽度图。

## 已有的基础（不重做）

- 网页对话：流式回复（`coach-stream`）、来源卡（`CoachSources`）、确认卡与草稿（`prepare_*` 工具只出草稿，UI 确认才写）、对话历史与删除。
- 批准账本：`AgentStore`（`src/services/agent/store.ts`）的预览 → 批准 → 执行，带内容哈希、上下文修订号与回执；整份训练计划在这里生效。
- 进阶引擎：`@liftcut/core/progression`（下次重量与理由，只用确认过的实际值）。
- 同意：`COACH_CONSENT_VERSION` 一个开关；同意文案用一段文字概括会发送的内容（消息、最近六轮对话、身体/饮食/训练记录、生成计划所需的设置），不是从字段清单生成，新增字段时文案不会自动跟着变。
- 计划生成：`prepare_training_program` 里组数和 RPE 的变化（`sets_delta`、`rpe_delta`）仍由模型给出，这是方案第 1 节缺口 1，M2-2 的封闭修改类型取代它在复盘中的作用。

## 清单

| 编号 | 内容 | 关键约束 | 验证 |
| --- | --- | --- | --- |
| M2-1 | **发送数据白名单**：核心包定义 `MODEL_DATA_CATEGORIES`（类别、包含的字段、用途），读工具的返回值按白名单逐字段过滤；网页同意界面改为从同一份列表渲染，同意版本随列表哈希变化 | 规则 3：新增字段必须同时改列表；未列出的字段一律不发 | 单元测试：每个读工具的输出字段 ⊆ 白名单；改列表而不改同意版本时测试失败；W1b 截图 |
| M2-1b | **白名单覆盖其余读工具**：`plan_context`（计划快照与个性化依据）和 `current_workout`（进行中训练）的返回值同样按白名单过滤，并补对应类别 | 同 M2-1 | 同 M2-1 |
| M2-2 | **封闭修改类型**：核心包 `review-changes.ts` 定义复盘可提出的修改：`nochange`、`switch_rule`（线性 ↔ 双重进阶）、`deload_now`、`adjust_sets`（±1，限处方范围）、`replace_exercise`（只能选动作目录的替换候选）。每条带 `evidence`（引用的训练/组 ID）。纯函数 `applyChanges(plan, changes)` 产生新计划，数字仍由进阶引擎算 | 规则 1、2：模型不给具体重量；新增类型必须同时有校验、应用和测试 | 单元测试：每种类型的应用、越界拒绝、未知类型拒绝、证据引用不存在即拒绝 |
| M2-3 | **训练后复盘（服务端）**：训练结束后按需生成复盘：读本次与近期记录（只经白名单），模型输出 M2-2 的封闭 JSON 或 `nochange`；服务端校验类型与证据存在，结果作为账本里的待批准运行保存 | 模型不写库；长期计划改动只走账本 | 产品 PostgreSQL 测试：生成、校验失败、证据造假、他人数据不可读 |
| M2-4 | **逐条接受与回滚（网页）**：复盘卡逐条接受/拒绝，按接受的子集计算新计划并走账本批准执行；执行前快照，一键回滚是一次新的补偿执行（恢复快照），不删除历史 | 撤销是补偿；幂等；冲突（计划已被改）时暂停并让用户重新预览 | W1b Playwright：部分接受、回滚、重复点击、过期预览；390 宽截图 |
| M2-5 | **复盘录制回放评测进 CI**：合成历史 + 录制好的模型响应（不调用付费接口），在 CI 中回放 | 指标：“不该改时改了”次数、证据引用真实存在率、类型合法率 | CI 新步骤；结果写入研究日志 |
| M2-6 | **手机端对话**：App 内对话页，复用 `/api/coach` 流式接口（Bearer 认证）、来源卡、确认卡；确认后的写入仍进 SQLite 发件箱 | 规则 4：手机与网页同一写入路径 | App 网页导出端到端：流式显示、确认后写入、未确认不写 |
| M2-7 | **手机端复盘卡**：训练结束后在 App 内显示复盘，逐条接受与回滚走 M2-4 的同一接口 | 同 M2-4 | App 网页导出端到端 + 截图 |

## 不做

多智能体编排、通用长期记忆、向量数据库、附近餐厅推荐（AGENTS.md 范围外）。复盘不自动执行：每条都要用户接受。

## 需要维护者决定的点（开始 M2-3 前再确认）

- 复盘是训练结束后自动生成，还是用户点“复盘”才生成（自动生成意味着每次训练都调用一次模型，有费用）。建议：用户点按触发，默认不自动。
