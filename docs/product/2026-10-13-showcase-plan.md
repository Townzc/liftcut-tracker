## 1. 定位

> 在健身房里，点一下或说一句就把训练记好；没做的不会被编出来；断网也不丢；每条建议都能看到依据。

第一批用户是维护者本人，再加 3–5 位有训练计划、规律去健身房的朋友。新手继续使用已有 `/demo`。

和 Hevy、Strong 这类点按式记录应用相比，本项目的差异不是“能聊天”，而是：

1. **偏差和更正能用一句话完成**：“全按计划，最后一组只做了 8 个”“刚才最后一组其实 7 次”。
2. **记录可信**：未报告的值保持未知，目标值永远不会被当成实际值。
3. **现场局部调整**：器械被占或今天只有 40 分钟，只改本次，不动长期计划。
4. **每次写入都可追溯**：哪句话、哪次点按、哪个提案，产生了哪条记录。

## 2. 不可违反的规则

这些规则优先于任何界面或模型改动；违反任何一条都阻止合并。

1. **计划不等于实际。** 目标组数、次数、RPE 只属于处方；只有用户点按确认或用户亲口报告的值才进入实际记录。
2. **未知是 `null`，不是 0。** 未报告的重量、次数、RPE 存 `null`；统计、图表、导出、卡路里估算都必须处理 `null`，不允许在下游重新 `?? 0`。
3. **模型不直接写库。** 模型只做两件事：把用户的话解析成草稿，或者生成提案。写入只有两个来源：
   - 用户的明确操作（点按、或“记下……”这样的明确指令），走记录写入路径；
   - 用户批准的提案，走 #62 已有的批准账本。
4. **每次写入都幂等。** 每条记录由客户端生成 UUID，服务端在本人权限内按 UUID 去重；同一版本重试必须得到同一结果，内容冲突必须拒绝。更正和撤销用事务中的版本检查推进 `revision`，旧请求不能覆盖新版本；仅用无条件 upsert 不能满足这些要求。
5. **撤销是补偿操作。** 撤销把记录标成 `voided` 并留下事件，不假装过去没有写过。
6. **改长期计划必须走批准。** 本次调整只影响本次训练；要改以后每次，必须走 #62 的预览 → 批准 → 执行。

## 3. 按风险分级的授权

| 动作 | 授权方式 | 理由 |
| --- | --- | --- |
| 记录一组（点按、或“记下卧推 50 公斤 10 个”） | 直接写入，立刻给出回执卡和一键撤销 | 授权来自用户明确操作；风险主要是解析错误，回执 + 撤销比事前确认摩擦更小 |
| 更正某一组 | 直接写入新版本，回执卡显示“第 3 组：8 → 7”并可撤销 | 同上，且目标组必须由确定性代码定位，定位不唯一时先问 |
| 本次替换动作、缩短本次时长 | 一次点按确认卡片上的新版本 | 影响后续多组，需要用户看一眼 |
| 修改长期计划 | #62 的批准流程（不可变提案、内容哈希、上下文版本、幂等执行、回执） | 影响以后所有训练 |
| 常去健身房的器械、单位偏好 | 用户在设置页直接编辑 | 不需要模型自动“记住”，避免误记 |

## 4. 系统结构

```text
浏览器（今日训练卡 + 输入框 + 回执卡）
  ├─ 本地发件箱（IndexedDB）：每条写入带客户端 UUID，联网后按顺序补发
  │     └─ Supabase（RLS）：workout_sessions / set_logs，按 UUID upsert
  ├─ /api/ai/parse-log（服务端，DeepSeek）：只返回解析草稿，不写库
  │     └─ 先走确定性规则解析器，解析不了再调用模型；输出经 Zod 与业务规则校验
  ├─ /api/agent/runs（#62 已有）：长期计划的提案、批准、幂等执行、回执
  └─ 轨迹查看器：一条记录 → 来源（点按 / 原话 / 提案）→ 解析结果 → 写入事件
```

设计要点：

- **记录只有一条写入路径。** 点按和一句话记录都把结果交给同一个发件箱，所以离线、重试、幂等只需要实现一次。
- **模型输出是不可信数据。** 解析结果经过 schema 校验和业务约束（重量范围、次数范围、单位、目标组必须存在）后，才会被当成草稿交给用户。
- **进阶建议由确定性规则计算**（例如双重进阶：每组都达到次数上限后，下次加最小增重），模型只负责用自然语言解释原因。
- **长期“记忆”就是结构化训练历史加用户可编辑的设置**，不另建通用记忆系统。

## 5. 数据模型（增量迁移，不重建）

新增两张表，均开启 RLS，只允许本人读写：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `workout_sessions` | `id uuid`（客户端生成）、`user_id`、`local_date`、`timezone`、`training_plan_id`、`week_number`、`day_number`、`status`（`active / ended / cancelled`）、`prescription jsonb`、`started_at`、`ended_at` | 开始时保存当天处方快照，之后计划改了也能还原当时的目标；每个用户至多一个 `active` |
| `set_logs` | `id uuid`（客户端生成）、`session_id`、`user_id`、`plan_exercise_id`、`exercise_name`、`set_index`、`weight_kg`、`reps`、`rpe`（三者都可为 `null`）、`input_unit`（`kg / lb`）、`weight_source`、`reps_source`、`status`（`done / skipped / voided`）、`revision`、`source_ref`、时间戳 | `source` 取值：`user_entered`、`user_confirmed_prefill`、`user_said`；RPE 只来自用户，不设来源字段 |

旧数据兼容：

- 旧表 `workout_log_exercises` 的三个实际值字段改为可空。历史中 `actual_rpe = 0` 一定不是真实 RPE，迁移时改成 `null`；重量和次数的 0 无法判断真假，保持原值，并在界面标注“旧记录”。
- 旧记录中等于目标 RPE 的值可能是旧界面预填的，无法区分，在已知局限中写明，不做猜测性修正。
- 新旧数据**不双写**。历史页、个人纪录、图表通过一个读取适配器同时读取两种来源。

## 7. 展示亮点的具体要求

### 7.1 断网模式（首选亮点）

- 发件箱存在 IndexedDB，联网后按创建顺序补发；服务端按 UUID 去重并原子检查版本，同版本同内容返回原结果，同版本不同内容或过期版本拒绝。
- 更正和撤销都带 `revision`，旧版本的补发不能覆盖新版本。
- 页面始终显示“已同步 / 待同步 N 条 / 同步失败”。
- **国内环境注意**：微信内置浏览器的离线能力按实际系统和版本验收，不预设 Service Worker 一定可用。离线记录的最低承诺是“页面已加载且保持打开”，只靠 IndexedDB 保存发件箱；Service Worker 缓存只作增强。IndexedDB 不保证断网后刷新或冷启动能加载页面。需要在真机（iOS Safari、安卓 Chrome、微信内置浏览器）上分别验证，记录版本、刷新/重开结果和存储不可用时的提示。

### 7.2 轨迹查看器

- 任意一组记录可展开：来源（点按 / 原话 / 提案）、原始输入、规则或模型解析结果、校验结果、写入与撤销事件。
- 长期计划变更直接复用 #62 已有的事件流与回执。
- 不展示模型的推理过程，只展示输入、输出和状态变化。

### 7.3 解析评测进 CI

- 约 150 条中文、英文、中英混杂的记录语句，覆盖单位（kg / lb / 磅 / 公斤）、多组、部分 RPE、“同上”、更正、跳过、只说“练完了”。
- 标注明确写出哪些字段应为 `null`。
- 指标：字段准确率、**编造次数**（标准为空但给出了值）、遗漏率、更正定位准确率。
- CI 只运行确定性规则解析器和**录制好的模型输出**，不在 CI 里调用付费接口；实时模型评测由维护者手动运行，结果单独记录，标明日期和模型版本。
- 编造次数大于 0 时 CI 失败。

### 7.4 语音记录（可选）

浏览器自带语音识别在国内不可靠，需要接入国内语音识别服务或自部署模型，选型前先核实可用性和费用。转录文字必须显示给用户，数字或单位不确定时追问。

## 8. 国内合规（上线公开前必须完成）

以下是工程上需要落实的事项，不是法律意见；正式对公众开放 AI 功能前，以当时有效的规定为准再核实一次。

1. **生成式 AI 应用登记与适用范围。** 网信办公告明确：直接调用已备案模型能力的应用或功能由地方网信办开展登记，上线后应公示模型名称、备案号或上线编号。公开 AI 功能前，维护者须向属地网信部门核实本应用的适用范围和手续，完成适用的登记及公示。未完成前不公开开放；受邀测试只是产品访问限制，**不等于法律豁免**，测试是否属于向境内公众提供服务仍须核实，不能仅凭“免费”或“邀请码”判断。[官方公告，2026-09](https://www.cac.gov.cn/2026-09/14/c_1791136833136332.htm)；[《暂行办法》第二条、第十七条](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)。
2. **AI 生成内容标识。** 《人工智能生成合成内容标识办法》自 2025-09-01 起施行。产品要求所有 AI 生成的建议、解释在界面上加“AI 生成”标识；提供下载、复制或导出时保留适用的显式标识，并核实对应文件格式的隐式标识要求。界面标签只是其中一项，不能据此宣称已满足全部标识义务。[官方办法第四、五、八、十四条](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。
3. **个人信息保护。** 体重、身体数据、训练与健康相关信息按敏感个人信息处理：
   - 处理前单独征得同意；
   - 把这些数据发给 DeepSeek 前单独告知并征得同意，隐私政策写明接收方；
   - 提供账号删除与数据导出；
   - 只向模型发送当前任务需要的最少数据。
4. **公开仓库与演示账号**只使用合成数据，不提交真实健康记录。
