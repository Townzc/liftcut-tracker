# 首页当前计划

2026-10-16。把已确认的训练计划从聊天里的长面板收进首页，保留 Agent 的生成、调整和批准流程。

## 用户路径

- 首页「当前计划」卡片 → `/current-plan`：日历进度、实际已记录训练日、今日推荐动作、训练日切换。
- 「开始记录」→ `/current-plan/workout`：携带选中的周/日，复用现有训练发件箱、快照、幂等和撤销。进入页面不创建会话，明确点「开始训练」才创建。
- 已有进行中会话优先提供「继续记录」，使用会话自己的处方，不拿当前计划覆盖它。
- 「让 Agent 调整计划」只填入对话草稿，不自动发送或应用。
- Agent 中新方案默认是紧凑卡片。「查看方案」打开可滚动的完整预览，底部保留确认/放弃。确认成功收起为简短回执和当前计划入口；刷新可恢复尚未确认的提案。
- 底栏仍只有首页、Agent、设置；当前计划及记录子页选中首页。查看计划复用已加载的本人计划/历史，不调用模型。

## 进度的含义

- 周计划按 `max(weekNumber) × 7` 计算日历周期；12 周为 84 天。开始日期取当前计划版本的 `created_at`，按浏览器当地日期计算，跨夏令时不按 24 小时凑天数。显示上限为总天数，过期后仍能继续查看/记录漏练内容。
- 「已记录训练日」只认当前用户、当前计划 ID、已结束且有实际完成组的记录；相同周/日多次训练不重复计数。空会话、未结束、撤销、未知次数及其他计划的历史不会填入进度。
- 今日动作按未记录训练顺序推荐，不把第 1/2/3 次冒充星期一/二/三，也不因日历过去而自动跳过漏练。用户可主动选择其他训练日或休息。
- 目标组数、次数、RPE 与实际数据分开。显示动作不会写入任何实际记录。没有记录的训练日显示「未记录」，不声称用户一定没有练过。

## 边界

- 本轮不添加数据库迁移，不改变模型预算、原批准账本、写入鉴权或 RLS。
- 当前计时属于当前计划版本；批准替换成新计划版本会重新计时。尚未提供自定义开始日期、跨版本累计周期或精确到非整周的任意天数计划。
- 饮食方案同样改成紧凑预览与确认，饮食计划详情仍可在 Agent 查询；首页进度当前对应训练计划。
- 手机尺寸 Chromium/WebKit 和微信 UA 模拟不代表实体手机或实际微信内核验证。

## 验证

- 单元：日历边界、上海/洛杉矶时区、夏令时、计划结束、缺失日期、未结束训练、重复训练、跨账号/计划、撤销与漏练。
- 浏览器 → API → PostgreSQL：计划确认后出现在首页；进入记录页零自动写入；选择训练日、明确开始、填写一组、结束、刷新后计数与下一次训练一致，未填重量/RPE 为 NULL。
- 原计划回归：长周期生成、刷新恢复、批准时切页、丢响应后幂等恢复、旧计划结构调整、饮食确认、过期提案及账号隔离。
- 最终 CI、正式站 Chromium/WebKit 验收和合成账号清理记录见本次本地发布交接。
