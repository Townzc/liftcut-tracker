# 访客答非所问与历史事实查询

2026-10-16

## 原因

访客没有账号，不调用 `/api/ai/coach`。本地 `coachIntent` 只识别少数完整问候句；例如「你好 你能做些什么」「你能做什么呀」落入没有活动训练的通用分支，被错误回复为先开始训练。旧的本地身体查询仅识别 ISO 日期、今天和昨天，「两个月前」会被忽略并返回最近记录。六轮限制本身并没有删除身体记录。

## 行为

- 访客问候/能力介绍明确说明本机数据模式；未知聊天不再冒充训练指令。自然对话、Agent 补录和计划生成仍要求登录及现有同意流程，没有开放匿名模型接口。
- 访客补录请求说明尚未保存，引导登录后重新确认，不再展示无法确认的草稿。访客隐藏不可用的云端历史入口；记忆说明区明确访客聊天刷新清空、本机记录与无痕存储的边界。
- 共用日期解析器处理指定日期、过去 N 天、本周、N 天/周/月/年前。月份按日历回退并在月末取有效日期；例：2026-10-16 的两个月前是 2026-08-16，2024-03-31 的一个月前是 2024-02-29。
- 本地查询显示实际日期。无记录、未知字段、补偿撤销和其他账号数据不能用最新值/目标值代替。无法明确解析的时间条件要求澄清，不静默查最近数据。未支持本地任意比较、自然时间区间或模糊月份；登录模型可用现有日期工具处理更多范围。
- 明确的历史体重问题会在模型调用前读取对应日期；模型 `read_records` 同样受共享日期约束，避免自行扩大为最近 28 天。读取上限仍是每次最多 93 个日历日/200 条记录，允许查询很早以前的单日；它不是 93 天保留期。

## 数据与记忆

1. 聊天：当前所选对话最近六轮完整消息进入模型上下文；账号历史独立保存，其他对话、未完成回复不会自动送给模型。
2. 事实：已确认身体/饮食条目保存在 `personal_record_events`；旧身体/饮食记录和实际训练由现有适配器读取。日期、明确数值、原话、回执和补偿撤销独立于聊天。新对话或删除聊天不会删业务记录；未确认数字不自动变成事实。
3. 偏好与计划：使用可编辑的设置和当前计划；计划修改仍走不可变预览、显式批准、幂等执行账本。未建设向量库或泛化长期记忆。
4. 访客：已有访客快照在当前浏览器 localStorage，没有云端备份。刷新可重新读取快照，但无痕会话关闭、清除网站数据、换设备不能保证保留。长期使用应登录，并明确处理已有访客数据的同步。

## 验证记录

- 基线 122 单测通过；修改后 125 单测通过（6 JavaScript + 119 TypeScript）。新增问候、日历跨月/跨年/闰年、过期聊天上下文、无记录/撤销/NULL 回归。
- 本地 PostgreSQL 18 项相关测试通过，包括两个月前实际记录、新旧读取、用户隔离、补偿撤销、幂等和历史权限。
- Chromium 12 项登录/历史/新用例通过。新用例通过真实页面确认补录，验证确认前数据库零写入，八轮后请求中已不含原数字，仍能通过服务端查询旧体重；刷新/新对话再次读取。
- 构建/类型通过；lint 无错误，仅两个既有研究脚本警告。首轮单测发现新增局部变量与旧变量重名，修复后全量通过；失败工具输出节选保留在本机发布证据目录，原完整文件已被成功重跑覆盖。
- 本地认证与模型为 HTTP 夹具，数据操作为应用 API 和真实 PostgreSQL；不将它们称为真实模型或真机测试。完整 CI、WebKit、部署和正式站结果另存发布交接。

全量 CI 首轮 76/77 浏览器通过，额外发现结束训练后立即回首页的同步问题。Trace 显示 `POST ...?action=end` 在切页时被旧页面清理中止（status -1），并非历史数据被删除。训练同步工作器移至账号级外壳，首次进入训练/Agent 时才启动，切页继续同步，账号退出/切换仍中止并隔离。新增测试故意挂起结束回执后回首页，释放回执后必须更新实际进度；不通过延长断言等待掩盖问题。最终完整回归在发布交接记录。

后续按用户反馈增加明确的查询区间和按日历查询入口；不能通过无限增大聊天上下文替代业务记录。
