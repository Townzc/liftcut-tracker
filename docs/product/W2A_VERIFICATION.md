# W2a：先保证一句话草稿可信

日期：2026-10-13（洛杉矶）。接续 [第 2 周任务](WEEK2_CODEX_BRIEF.md)。本次无数据库变更、GPU、模型调用或训练，不改变 W1 的线上写入流程。

## 为什么先做纯解析

一句话记录减少填表，但错误的默认值会再次污染 W1 修好的数据。先把解析和写入分开：输入只有原话、当前动作目录、用户选中的动作、已有实际记录；没有计划次数、重量或目标 RPE。解析函数只返回草稿或澄清原因，不持有网络/数据库能力。

实现位于 [workout-log-parser.ts](../../src/lib/workout-log-parser.ts)。例如：

- `卧推 50 公斤 10、10、8，最后一组 RPE 9` → 三组重量 50、次数 10/10/8、RPE `null/null/9`。
- `10次` → 重量与 RPE 都为 `null`；明确报告 0 次则仍是 0。
- `刚才最后一组其实7次` → 唯一已完成组的 ID、当前 revision 和仅含 reps 的补丁；其他字段保持原值，不输出“清空”。
- `练完了` → 结束草稿，不制造任何完成组；下一层仍需明确确认。
- `全按计划`、`同上`、缺少重量单位、多组 RPE 范围不明、多动作、未知动作、目标不唯一 → 澄清。

`explicit` 仅标记原话中是否有明确记录/更正/跳过动词，**不是授权凭据**。W2b 服务端必须从认证用户和实际操作重新确定权限，不能接受客户端或模型传来的 `approved=true`。本次没有接入自然语言 API、界面或自动写入。

## 实际步骤与结果

1. **先定范围**：把 W2 拆为纯解析与事务/界面两项 PR，防止同时修改授权、写入、模型和表单而无法定位错误。重量支持 kg/lb/公斤/千克/磅，磅按 0.45359237 换算并保留原单位/原数值。
2. **补上下文保护**：组目标必须存在、ID/槽位唯一、revision 有效；跳过或撤销的槽位仍被占用。仅按明确选中动作或唯一名称/别名定位，不模糊猜测动作。未命名动作且没有选中动作会澄清。
3. **人工编写合成预期**：[语料](../../tests/fixtures/workout-log-corpus.ts) 为 10 个语法家族 × 15 个变体；74 中文、40 英文、36 混合。预期不调用解析器生成，数值和空值均显式写出。这是开发集覆盖，不是 150 个独立任务或外部泛化证明。
4. **实现评测**：[评测器](../../tests/helpers/workout-parser-eval.ts) 逐字段比较完整草稿，同时要求正确拒绝和正确接受。[6 项测试](../../tests/workout-log-parser.test.ts) 覆盖语料、评测器反例、历史值独立性、错误上下文、撤销/跳过槽位及草稿边界。
5. **实际运行**：首次 6 项针对测试通过；全套 66 项单元测试（8 MJS + 58 TS）通过。`npm run eval:workout-parser` 输出 150/150 契约匹配：79/79 草稿、71/71 澄清、755/755 字段匹配、153 个应空字段编造数 0、207 个明确数字字段遗漏数 0、更正目标 7/7。
6. **检验指标不会自欺**：将解析器替换为“全部拒绝”时，草稿匹配为 0、遗漏大于 0；故意填 RPE=8 时编造指标大于 0；故意换组 ID 时更正定位为 0。CI 既检查空值，也检查完整输出，不允许靠拒绝所有输入拿高分。
7. **工程检查**：lint 0 error、仅 2 个既有研究脚本警告；生产构建通过。解析器尚未导入应用，不能把这次构建当成自然语言页面验收。

## 已知局限与下一步

当前只接受限定语法，不评估自由口语或真实用户接受率；中文数词、复合动作语句、“同上”、重量/RPE 更正等未支持形式会要求澄清。更正“最后一组”定义为当前动作编号最大的未撤销完成组，不是任意跨动作的最近消息。新记录自动选择尚未占用的组号；会话是否结束、并发版本是否过期必须由后续写入层重新核验。

W2b 接下来做认证后的解析 API、原子批量命令、回执与补偿。点按和句子共用 TodayStore，全部组一个事务；更正撤销要恢复原值并递增 revision，冲突时不覆盖后来修改。接入后再做浏览器 → API → 数据库的断连/重试和手机界面验收。**W2a 完成不代表第 2 周整体已完成**。

学习点：规则解析覆盖确定的常用句型，模型只在未来有明确需要时补充草稿；真正保证“没做的不编造、旧请求不覆盖”的仍是空值契约、用户授权和数据库事务。
