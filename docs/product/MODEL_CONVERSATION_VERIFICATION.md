# 开放式模型对话：验证与发布边界

2026-10-14。接续 [本轮范围](MODEL_CONVERSATION_BRIEF.md)，保留首页 / Agent / 设置的黑白界面。用户已明确授权测试后上线；本页记录实现提交之前的观察，最终合并、部署和托管验收另存发布记录，避免把待执行事项写成结果。

## 实现与原因

- Agent 用已有 DeepSeek 服务做有限工具循环，支持自由提问、追问、本人记录查询，以及身体、饮食和当前训练补录。查询每次重新读取本人数据；来源卡显示日期、读取时间和实际记录。目标值与实际值分开，未知营养不估算。
- 模型只选择工具和原话片段。服务器从片段解析数字、单位和日期，生成绑定账号、原文、UUID、草稿及训练上下文的签名。用户点确认后才进入原有写入队列；数据库继续检查版本、幂等和补偿。没有另开模型直写接口。
- 使用前单独说明模型接收方及数据范围，用户主动开启；仅保留当前页面最近六轮上下文，可随时关闭并清空。已确认记录保留原话和所用片段，不保存整段聊天或内部推理。账号切换不继承对话或同意状态。
- 每次最多 5 步、4 次有限范围读取，限制输出与超时；每账号每分钟 6 次、滚动 24 小时 60 次，额度通过数据库原子预留。取消、模型失败、来源读取失败和限额有明确状态；失败不等于空历史。
- 新迁移只增加无聊天内容的调用计数表及本人只读权限，运行角色无 superuser/BYPASSRLS。新增独立服务端签名密钥。修补实际审计发现的运行时依赖问题，Next 升至 16.4.1；生产依赖审计为 0，不能据此称开发依赖也无问题。

## 发现与修正

- 真实模型第一次把“那昨天呢”读取成过宽日期范围，后续服务端为单日追问收窄读取；第二次“今早”未被日期校验接受，扩展常见时间短语后 8 场景全部通过。初次失败和最终结果分别保留。
- 全回归首次 41/42：旧多标签页撤销测试在异步入队前读到上一操作的“已同步”，随后重载了正在提交的标签页。测试现在等待本次撤销预览关闭后再查同步，未放宽租约或删掉重试断言。
- 第一次浏览器启动遇 Windows 保留端口，测试认证端口支持环境变量，本地使用 5440；CI 仍用原默认端口。WSL 退出导致数据库连接中断后，保留本轮测试专用前台存活进程。两者属于测试环境问题。
- 依赖刷新引入 react-hooks lint 插件的新版本并触发旧组件额外规则，固定回原 7.0.1 基线，未关闭规则。截图发现确认后还留着模型“尚未保存”的旧文案，确认入队后清除该旧状态。

首版 #79 的 8 项精确 CI 全通过，合并树一致，正式域名已运行 `0b7785b`；增量迁移和受限权限核对通过。真实 GoTrue / Vercel / Supabase / DeepSeek 已跑通独立同意、中文数词体重、保存后查询、日期追问、饮食离线确认/丢响应后重试以及自然训练补录。全部使用两个人工账号。

新增浏览器断言特意让模型漏报当前训练来源、重复查询同一天，检查服务器仍返回完整且唯一的来源，以及活动会话不计为完成。重新运行 87 单元、完整 43 浏览器、构建/类型/lint，通过；数据表与写入路径未修改。新提交仍需精确 CI 后重新部署，并在旧测试记录上继续验收，避免重放已提交的补录。证据见 [来源修正索引](evidence/coach-model-sources/verification.json)。

追加复核：只检查当前消息的“目标/计划”不够，上一轮的目标数值可能被后续“记下来”引用。现在每个原话片段也检查提供该片段的用户消息；目标或假设不能成为实际值来源，明确重新报告的相同实测数值仍可使用。同时拒绝把“80 kg”中的“0 kg”、十八次中的八次当作完整报告。增加跨轮体重/训练反例、真实报告正例、数字片段与 HTTP 恶意模型回归，最终 89 单元、43 浏览器、构建和类型通过，lint 仍仅 2 个原警告；输出记录于同一索引。
