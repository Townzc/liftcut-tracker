# 第 3 周任务：断网记录与本次动作替换

基于 [产品方案](2026-10-13-showcase-plan.md)。W2 已上线；本周不需要 GPU、模型调用或研究改动。

实施状态：W3a 离线发件箱与 W3b 本次替换均已完成正式验证，分别见 [W3a](W3A_VERIFICATION.md)、[W3b](W3B_VERIFICATION.md)。离线冷启动与真机 iOS/Android/微信仍未验收，不能由桌面移动视口测试替代。

## W3a：离线发件箱（先完成并独立发布）

- 原因：内存中的重试在刷新/关闭后丢失；不能把断网等同于服务器未提交。
- 每个账号使用独立 IndexedDB 状态。先事务落盘，再显示待同步；存储失败不显示成功、不发送未经落盘的写入。
- 今日卡开始、逐组保存/更正/跳过/撤销、整句确认/补偿、结束走同一队列；UUID、版本、请求字节冻结。已开始的训练支持连续离线操作；新训练须先取得云端计划快照。
- 本机规则解析可离线预览，云端继续核验完整上下文并重新解析；本机投影不是已提交的实际数据，回执须标明待同步。
- 同一账号按落盘顺序发送，IndexedDB 原子领取与有限租约处理多标签页/崩溃。未知响应只能原请求重试；后续操作不越过它。
- 服务端仍以真实认证与 RLS 授权，另核对请求绑定的原账号；切换账号后不显示或发送其他账号的发件箱。
- 版本/内容冲突停止队列，展示本地操作与云端记录；只有明确放弃冲突及后续操作才重置，不自动提高版本或覆盖。401 暂停待重新登录。
- UI 区分已同步、待同步 N 条、同步失败、无法本地保存；有有限退避、手动重试、联网/重新进入恢复。
- 验收：断网三组→更正→撤销→结束再补发；离线整句与补偿；提交后丢响应+刷新/多标签重试；跨设备新版本拒绝旧队列；账号切换/过期；存储拒绝；空值与来源不变。
- 本 PR 不承诺离线冷启动/离线刷新页面可加载；不装 Service Worker。真机 iOS/Android/微信未实际测试前不得写通过。

## W3b：仅本次训练动作替换（后续独立 PR）

- 小型动作库与可解释替换条件、装备/部位限制；修改当前会话快照，不修改长期计划。
- 用户确认、幂等版本、可补偿回执；与离线队列和已有实际组的冲突必须预先设计。
- 先固定动作资料与验收，再实现；不把建议当作医疗/训练效果保证。

每个 PR 在 [产品日志](PRODUCT_LOG.md) 写不超过 15 行，详细原因、真实失败/修正、测试与上线证据放独立验证记录。精确最终提交全检查成功再合并上线。
