# 新账号初始化：演示数据不能成为真实历史

## 为什么紧接 W3a 修正

W3a 正式网站验收时，为测试跨账号隔离创建了两个全新的合成账号。独立查库发现旧明细总数从 100 变成 105；逐条核对确认原有 100 条没变，额外 5 条属于第二个合成账号。源码定位到 `ensureUserBootstrap`：只要账号没有训练计划，就会保存 `createDemoSnapshot` 的计划、训练、饮食和身体记录。它是既有行为，不是本轮离线队列重复提交。

这与产品“实际记录必须来自用户”冲突，所以先修这个确定问题，再推进 W3b 动作替换。没有推测或批量删除旧账号历史；旧记录来源无法自动可靠分类。

## 改动与边界

- 真实登录只确保 profile 和默认设置存在，不再自动创建计划或 observed health logs。
- 无计划账号使用原本已有的空计划读取视图，界面提示建立计划；不会用演示计划伪装成用户已选择的计划。
- `/demo`/访客演示使用的样例生成器保持原样；用户主动记录、导入和现有迁移流程不在本次变更范围。
- 无数据库迁移；不改已有用户数据、研究源、模型或批准账本。

## 验证与发布

在实际浏览器登录入口增加回归：无计划的第二个合成账号完成初始化与今日页读取，监控所有 PostgREST 写请求，除 profile/settings 外不得发出任何计划、训练、饮食或身体写入；无活跃会话、无训练日、无回执，开始按钮禁用。身份服务仍为本地 HTTP 契约替身，因此另需部署后的真实新账号验证。

本地生产构建的首次回归漏配 `NEXT_PUBLIC_SUPABASE_URL/ANON_KEY`，登录框未启用。观察到首例超时后终止后续无效运行，保留 [失败](evidence/w3a/bootstrap-browser-env-failure.log)；补齐编译时 loopback 环境后重新构建，不把它当作应用缺陷。测试和 lint 的最终输出见同目录，正式发布后另记录真实账号的空历史核对与清理。这里不提前声称生产修正验证完成。

最终本地 **70 单测、17 个浏览器场景全部通过**（新增登录初始化回归，其余 16 项完整重跑）；生产构建成功，lint 0 error / 2 条原有警告。见 [单测](evidence/w3a/bootstrap-unit.log)、[浏览器](evidence/w3a/bootstrap-browser.log)、[构建](evidence/w3a/bootstrap-build.log)、[lint](evidence/w3a/bootstrap-lint.log)。数据库事务实现未改，原 17 项 PostgreSQL 验证不冒充本次重新执行；CI 仍会执行全部检查。

下一步：先确认此修正后的真实账号初始化结果，再推进 W3b 的动作资料、会话变更版本与撤销/离线冲突设计。无需 GPU 服务器。
