# Agent 查询读取最新记录

2026-10-14，基于已经上线的 #77（`3027d573`）。本次修复来自真实托管验收中的失败，不是推测的问题。

## 发现

合成账号在真实 GoTrue → Vercel → Supabase 路径完成训练、整句更正与补偿后，立即询问「本周训练」，回答为 0 次。服务器的训练已经结束，组记录为 8 次、重量/RPE 为 NULL、版本为 3。保存回执先到达，后台的 `fetchUserDataBundle` 还需要继续读取其他表；等待 history HTTP 200 并不等于 Zustand 缓存已经更新。

另外，页面初次加载时询问身体/饮食，旧实现只提示等待后重新询问；新查询应自行读取，而不要求用户再发送一次。失败记录保存在 [托管失败摘要](evidence/agent-freshness/hosted-failure.json)。

## 修复

- 每次已登录账号的数据查询单独等待最新读取，不依赖页面缓存刷新。旧历史和新补录并行读取，查询不修改全局状态或写入数据。
- 数据仓库增加严格读取模式：任何历史读取失败直接失败，不能用旧页面的空数组降级结果回答。整个历史读取共用 15 秒截止时间；个人补录读取同样限时。
- 离线、失败或超时明确提示无法读取，不返回“0 次”或“没有记录”。尚未同步的记录有独立提示；目标入口与支持范围的说明不需要网络。
- history API 也核对预期账号。身份仍以服务端真实认证为准，账号标头只用于拒绝切换账号后的旧请求。
- 等待时显示「处理中…」，确认写入、撤销补偿和队列语义保持原有路径。
- 手机首屏缩小欢迎区上下留白；390×844 英文界面明确检查发送按钮的下边缘不越过底部导航，避免按钮落入底栏区域。
