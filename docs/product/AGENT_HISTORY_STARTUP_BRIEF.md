# Agent 对话连续性、冷启动与鉴权分段

2026-10-15，接续 [查询提速](AGENT_LATENCY_BRIEF.md)。本轮处理实际反馈：从 Agent 切换设置后聊天消失，刷新不能恢复，也无法判断 AI 的记忆范围。

## 用户流程与存储边界

- 对话状态和请求控制器放到账号作用域的根 Provider；切换首页/设置不会卸载正在生成的回复。退出或切换账号才清理内存和该账号本机缓存并取消请求。
- 本机立即保留当前对话、输入草稿和未同步队列；历史 API 异步保存到本人账号，不阻塞输入框或模型请求。刷新恢复消息；另一浏览器登录后可从顶部历史入口继续。新对话从空上下文开始。
- 两张增量表使用强制 RLS 和受限运行角色。保存按消息 UUID/版本幂等处理；同一段对话的保存和删除使用事务锁，删除留下空墓碑，拒绝迟到的离线上传。查看历史不执行任何业务操作。
- 只保存聊天文字，不保存可执行草稿、签名、模型工具源数据或生成中的半成品。刷新中断的回复明确提示重发。历史中的补录草稿需要重新生成确认卡；计划预览仍通过既有批准账本恢复并显式确认。
- AI 仅使用所选对话最近六轮完整内容，不自动合并其他对话。身体、饮食、训练和设置事实仍按需查询最新数据库。新增“记忆范围”说明及同步状态；不是通用长期记忆，也未引入向量库。
- 本功能上线前只存在页面内存、已经丢失的对话无法找回。访客聊天仍仅驻留当前应用会话，云端历史需要登录。

## 性能改动与计时口径

- Agent 首屏仅导入轻量能力配置，避免加载模型 SDK 与完整工具模块；模型模块初始化与独立的鉴权请求重叠。`bootstrapMs` 只包含路由内动态模块加载，不包含平台唤醒和路由本身初始求值。
- 页面跳转使用 Supabase `getClaims()` 验证签名和有效期，缓存公开 ES256 验签密钥。数据和修改 API 仍独立调用 `getUser()` 做新鲜身份验证。回归覆盖签名篡改、过期、无会话和跨账户拒绝。
- 原子限额将锁/统计/插入三个数据库往返合成一次 SECURITY INVOKER 函数调用。锁后以独立 SQL 获取新快照，不把锁和计数塞进同一个可能读取旧快照的 CTE；保留每分钟 6 次、每天 60 次限制。
- 精确、独立的问候和能力介绍使用较短指令与最终回答工具；包含个人数据、修改意图、模糊表达或已有历史时保留完整工具路径。所有补录与计划修改仍先完整预览再确认。
- `authDetail` 区分客户端创建和 Auth 请求；`quotaDetail` 区分数据库内部锁、检查和插入。原有连接/事务/查询/提交时间保留。数据库往返耗时不能当作纯 SQL 时间，浏览器总耗时减服务端时间也不能当作纯网络 RTT。

## 验证与发现

主链路：手机聊天 → NDJSON 增量显示 → 切换设置继续生成 → 返回同一对话 → 云端保存 → 刷新/另一浏览器恢复 → 当前对话上下文 → 完整草稿 → 显式确认。

本地真实 PostgreSQL 测试发现首次并发插入在两条唯一索引之间可能死锁，已增加对话事务锁；删除与迟到上传同时执行不能恢复已删文字。测试同时验证原有身体记录保持不变。限额 10 个并发请求恰好成功 6 个。

首次全浏览器回归 58/63：四个旧断言仍假设刷新会清空聊天，现改为核对消息保留；一项新测试遗漏清理合成账号限额，导致后续无模型请求断言读到前一项计数，已补清理。保留原失败证据，不用重跑覆盖。最终结果见 [验证索引](evidence/coach-history/verification.json)。

手机覆盖包含 Chromium Android/微信 UA + 150 ms、约 1.6 Mbps 下载的弱网模拟，以及 iPhone 尺寸的 WebKit；验证流式、切页、草稿恢复、中文输入法组合事件和布局。它们不是实体手机、真实微信 X5/WKWebView 或运营商网络。

[Globalping 官方 API](https://globalping.io/docs/api.globalping.io) 的国内探针访问公开登录页与公开验签密钥端点；未向第三方发送登录信息或健康数据。首轮 6/6 HTTP 200：站点北京/深圳/广州 2.065–2.332 秒，认证公共端点北京/深圳/上海 0.691–0.809 秒。探针属于腾讯/阿里云机房，只证明这些时点/线路可达，不代表全国手机体验。

正式站同题对照、精确 CI 提交、上线状态与合成账号清理在发布交接中单独记录；本地验证不冒充正式部署或国内 P95。
