# 当前产品工程问答

2026-10-14。本页只描述当前实现；历史模型训练结果见原研究报告，不把规则解析成功当作模型泛化能力。

## 为什么首页不再摆满统计卡片？

维护者反馈原导航和模块过多。主要任务是记录和查询，所以主导航收敛为首页、Agent、设置。首页保留可展开的补录，Agent 统一读取训练、饮食和身体历史；详细训练和计划工具按需打开。减少入口并不删除已有用户历史。

## Agent 现在到底能做什么？

当前对话层是规则与数据查询。它能展示明确范围内的已存记录，把明确数字和单位解析为草稿，确认后调用受限 API；训练更正、跳过、结束和本次动作替换沿用已有流程。它不会推断没填写的热量或 RPE，不提供自由模型问答。这是可以演示、测试的工程交付边界。

## 断网与请求结果未知有什么区别？

断网时，操作先写入本机持久化队列；存储失败则不发送。响应丢失时，服务器可能已经提交，因此重试必须保持 UUID 和请求内容不变。数据库返回同一回执；改变内容的同 UUID 请求会被拒绝。训练请求还有顺序、版本和上下文保护；独立的身体/饮食新增记录不互相依赖，使用按账号分区的独立请求键。

## 为什么撤销不直接 DELETE？

删除会抹掉原话和发生过的事实，也无法解释迟到重试。补偿事件保留原记录，查询投影排除已撤销项；同一撤销重复提交返回原回执，迟到的创建重试不能让它重新生效。受限运行账号没有新账本的 UPDATE/DELETE 权限。

## 如何证明“没编造”而不仅是界面显示为空？

同时检查解析预期、HTTP 请求、真实 PostgreSQL 中的 NULL 和导出结果。计划字段与实际字段分开；身体目标查询不冒充实测数据，食物未知营养不补零。测试包含另一个账号、负向权限、响应丢失、明确的 0、撤销后重试和本机存储故障。自动测试使用人工合成数据；没有临床有效性或任意口语泛化结论。

## 轨迹查看器展示什么？

组记录可展开版本、写入事件、实际值和确认原话；个人补录显示输入方式、保存时间、原话及补偿撤销时间。接口按真实登录账号及 RLS 读取，不依赖客户端传来的用户 ID 授权。它展示输入和状态变化，不展示模型推理。

## 还没完成什么？

真机微信/iOS/Android、离线冷启动、关闭页面后的后台发送、自由模型解析、跨页面聊天历史和正式 90 秒录屏尚未完成。旧身体/饮食详情页仍只展示旧存储，新的可空补录在 Agent 与完整 JSON 导出中查询；没有把缺失值映射回旧表的非空字段。后续统一详情读取适配器时必须继续保留 NULL。
