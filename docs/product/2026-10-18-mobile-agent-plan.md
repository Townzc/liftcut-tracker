# LiftCut 下一阶段：手机 App + 训练 Agent

2026-10-18 制定。本文件是**方案**，不代表其中功能已经实现。它接续 [展品方案](2026-10-13-showcase-plan.md)：那份方案的第 2 节规则继续有效；第 0 节中“只做网页、不上应用商店”的决定由本文件改为“最终上线手机 App”。

## 0. 结论

- **当前状态**：10-13 到 10-17 合入了 #64–#92 约 30 个 PR。原 5 周方案的 W1–W4 已全部上线到网页（可信记录、一句话记录、离线发件箱、本次替换、Agent 对话、计划生成与批准、首页当前计划、访客 AI、结构化健身记忆）。剩余缺口集中在**真机、国内网络、真实试用和离线冷启动**。
- **为什么转向手机 App**：用户在健身房带的是手机。网页已记录的最大局限正好是“离线冷启动”和“微信/真机未验证”，这两点用原生 App 才能根本解决。
- **技术选择（建议）**：Expo（React Native）原生客户端 + 单仓库共享领域代码 + 现有 Next.js API 与 Supabase 继续作为后端。网页保留，作为计划管理、历史和演示入口。
- **Agent 方向**：参考 opengym，补上**确定性进阶引擎**（数字由代码算），再做**训练后主动复盘 Agent**（只能提出封闭类型的离散修改、逐条接受、可回滚）。研究向亮点是**端侧蒸馏小模型**（已决定开启），断网也能一句话记录。
- **上架**：国内应用商店要 APP 备案、生成式 AI 登记，通常还要软著，周期以周计，维护者决定 Apple 开发者账号在本轮升级完成后注册；备案和软著周期长，建议提前办理。在此之前用安卓安装包给朋友试用。

**原方案没覆盖、现在暴露出来的三个缺口：**

1. **没有确定性进阶引擎。** 计划中的组数和 RPE 变化由模型给出（`training-program.ts` 中 `sets_delta`、`rpe_delta`），下一次用多重的重量没有可审计的规则。
2. **训练中的体验仍是网页表单。** 没有组间计时自动开始、屏幕常亮、本组破纪录提示、超级组、计时类动作。
3. **没有 PWA 清单和 Service Worker。** 网页无法“安装”，也不能在断网时冷启动。

## 2. 参考 opengym：学什么、不学什么

[alexpcosta/opengym](https://github.com/alexpcosta/opengym) 是 openGym 的分支，增加了 AI Coach。它采用 **AGPL-3.0** 许可，LiftCut 是 MIT：**只借鉴设计思路，不复制代码、文案、图标、肌肉图路径或动作素材。**

| opengym 的做法 | 为什么好 | LiftCut 怎么用 |
| --- | --- | --- |
| 进阶引擎是历史记录的纯函数：线性、Greyskull、双重进阶、加时间；连续失败触发减载；每个目标都显示“为什么是这个数” | 不存计数器，改一组记录立刻得到正确的下一次目标；可审计 | 新建 `packages/core/progression`，只读用户确认过的实际值；未完成或未知的组算“未达成”，绝不推进 |
| “引擎管数字，AI 管计划” | 模型不碰下一次的杠铃重量，数学可离线、可测试 | 写入规则：模型只能选择进阶策略和计划结构，具体重量由引擎算 |
| AI 提案是**封闭类型的离散修改列表**（加/删/换动作、组数、次数、进阶策略、周安排），每条带依据，逐条接受，接受前快照可一键回滚 | 封闭类型就是安全边界：用户笔记里的恶意文字最多让模型“说”，不能让它发明新操作 | 训练后复盘 Agent 使用同样的设计，并接入现有批准账本 |
| 复盘提示词明确“没有必要就不改”，允许返回 `nochange` | 防止为了显得有用而乱改 | 把 `nochange` 作为合法结果，并计入评测 |
| 发给模型的数据是**白名单**，同意界面从同一份类别列表渲染；用不可逆的匿名标识代替用户 ID | 同意书和实际发送的数据不会脱节 | 正好满足《个人信息保护法》对敏感信息“单独同意、告知接收方”的要求 |
| 训练中：沿用上次重量预填、组间计时器、屏幕常亮、本组 PR 检测、超级组、计时类动作 | 健身房里真正省事的是这些，不是聊天 | 放进手机 App 的训练页 |
| 估算 1RM，超过 12 次不估 | 诚实的边界 | 照做 |
| 手机版用文件镜像作为持久副本，因为 iOS 会在存储紧张时清掉 WebView 存储 | 离线数据的真实风险 | 原生 App 直接用 SQLite，不依赖 WebView 存储 |

**opengym 没做到、LiftCut 可以超越的地方：**

- 它的手机版没有后端，**手机上没有 AI**；不上架，iOS 只能自己用 Xcode 装。LiftCut 要做的是“有云端 Agent 的原生 App，并且可以分发”。
- 它是单机 JSON 文件存储，没有并发、事务和多设备冲突处理。LiftCut 已有 RLS、事务、幂等键、补偿事件和离线冲突处理，这是全栈能力的核心证据。
- 它没有自然语言记录，也没有对“编造”的评测。

## 3. 目标架构

```text
liftcut-tracker（单仓库，npm workspaces）
├─ apps/web        现有 Next.js：网页、API 路由、计划管理、演示
├─ apps/mobile     新 Expo App：今日训练、一句话/语音记录、组间计时、离线 SQLite、Agent 对话
└─ packages/core   共享 TypeScript：Zod schema、规则解析器、进阶引擎、1RM、动作目录、契约类型

后端不变：Next.js API 路由（DeepSeek）+ Supabase（Auth、Postgres、RLS）+ 现有批准账本
```

**为什么选 Expo（React Native），不选 Capacitor 套壳：**

| 维度 | Expo | Capacitor 套壳现有网页 |
| --- | --- | --- |
| 现有代码复用 | 领域逻辑通过 `packages/core` 共享，界面重写 | 现有 Next.js 依赖服务端组件和中间件，要改成纯静态导出，改动面很大；或者直接加载线上网址，那就和网页没有区别 |
| 离线冷启动 | 原生 SQLite，天然支持 | 加载线上网址时无法离线启动 |
| 审核风险 | 正常原生 App | 只加载网页的套壳容易被认为功能过少而被拒 |
| 原生能力 | 本地通知（组间计时）、屏幕常亮、震动反馈、语音识别、后台任务都有成熟模块 | 需要逐个接插件 |
| 云端开发 | Claude Code 云端是 Linux，不能跑 Xcode；Expo 的云构建服务（EAS Build）可以在云端打 iOS 和 Android 包 | iOS 包必须在 Mac 上用 Xcode 构建 |
| 面试展示 | 同一套领域代码驱动网页和原生 App，是完整的全栈故事 | 容易被问“这不就是网页吗” |

**手机端认证**：现有 API 用 Cookie。手机端改为在请求头带 Supabase 访问令牌，服务端用令牌校验用户；不在客户端放任何服务端密钥。

## 4. 阶段规划

每个阶段都要有一个能在真手机上演示的结果。阶段之间按顺序做；每个阶段拆成多个小 PR。

### M0 共享核心与训练体验（约 1 周，不依赖任何待定决策）

- 建立 npm workspaces，把 Zod schema、规则解析器、动作目录、契约类型移到 `packages/core`，网页改为从这里引用；行为不变，现有测试全部通过。
- 新增**确定性进阶引擎**（线性、双重进阶、计时；连续失败减载），纯函数，附“为什么”文本；单元测试覆盖未完成组、未知值、减载、单位。
- 新增**估算 1RM**（只用确认过的实际值，超过 12 次不估）。
- 网页训练页先补：组间计时自动开始、屏幕常亮、本组 PR 提示。
- 网页补 PWA 清单和最小 Service Worker（只缓存外壳），作为 App 上架前的过渡。

### M1 手机 App 最小可用版（约 2 周）

- Expo App：登录、今日训练（沿用上次预填、点按完成、跳过、撤销、结束）、一句话记录（复用规则解析器 + 现有服务端补录）、组间计时本地通知、屏幕常亮、震动。
- 离线：SQLite 发件箱，沿用网页已有的客户端 UUID、顺序补发、冲突暂停语义；服务端接口不新增第二套写入语义。
- 冷启动：断网打开 App 能看到今天的处方并记录，联网后补发。
- 分发：先用开发构建和 Android 安装包验证；Apple 开发者账号在本轮升级完成后注册，届时再上 TestFlight。
- 验收：飞行模式下冷启动并记三组，联网后数据库恰好三组；双击、重发、两台设备同时修改的冲突都有确定结果。

### M2 App 内 Agent（约 1–2 周）

- 对话：流式回复、来源卡、确认卡，复用现有工具和批准账本。
- **训练后主动复盘**：结束训练后，Agent 读取本次与近期记录，输出封闭类型的离散修改（每条带依据），或者 `nochange`；用户逐条接受；接受前快照，可一键回滚。数字由进阶引擎算，模型只决定结构和策略。
- 发给模型的数据改为白名单，同意界面从同一份类别列表渲染。
- 评测：复盘提示词用合成历史做录制回放评测进 CI（不调用付费接口），指标包括“不该改时改了”的次数、引用依据是否真实存在。

### M3 展示打磨（约 1 周）

- 肌肉训练量图和年度热力图（自己实现，不用 opengym 的素材）。
- 更新 90 秒演示：断网冷启动记录 → 联网同步 → 一句话更正 → 训练后复盘逐条接受 → 进阶引擎给出下次重量和理由。
- README 架构图、面试问答更新。

### M4 端侧蒸馏解析模型（约 2 周，2026-10-18 已开启）

- 目的：断网时也能一句话或语音记录。
- 做法：用现有规则解析器和云端模型在合成语句上生成标注，蒸馏到约 0.5B 的小模型，量化后在手机上运行（React Native 上有 llama.cpp 的绑定可用，选型时核实）。
- 评测：沿用 150 条评测并扩充，核心指标是**编造次数为 0**；与规则解析器、云端模型对比字段准确率、延迟和离线可用率。
- 这是本项目里唯一重新打开模型训练的地方，与维护者“LLM 蒸馏 + Agent”的方向一致；不做 RL，不追加其他 GPU 实验。

### 语音输入（M1 之后任意时间，可选）

- iOS 可以使用系统的端侧中文语音识别；国内安卓没有谷歌服务，需要接国内语音识别服务或端侧模型，选型时核实可用性和费用。转录文字必须显示，数字或单位不确定时追问。

## 6. 规则（在展品方案第 2 节之上新增）

1. **引擎管数字，模型管结构。** 下一次的重量和次数只由进阶引擎从确认过的实际值算出；模型不能直接给出具体重量。
2. **Agent 只能提出封闭类型的修改。** 新增修改类型必须同时有服务端校验、客户端应用和测试。
3. **发给模型的数据是白名单。** 新增字段必须同时更新同意界面的类别列表。
4. **手机与网页共用同一套写入接口和幂等语义。** 不为手机另建写入路径。
5. **AGPL 代码隔离。** 不从 opengym 复制任何代码或素材；PR 描述中如果参考了它的设计，写明“仅参考设计”。

## 7. 指标

| 指标 | 目标 |
| --- | --- |
| 编造次数、重复写入、同步丢失 | 必须为 0 |
| 断网冷启动后记一组的耗时 | 先测基线，不预设目标 |
| 记一组的操作次数（点按 / 一句话 / 语音） | 先测基线 |
| 复盘 Agent“不该改时改了”的次数 | 录制评测集上为 0 |
| 国内真机首字和完整回复延迟 | 积累足够样本后再报告 P50 / P95 |
| 朋友试用：两周内实际记录的训练次数、手工修正次数 | 只记录，不美化 |
