# Agent 首屏与流式回复

2026-10-14，接续 [对话计划方案](AGENT_PLANS_BRIEF.md)。保持黑白三入口与对话内确认。

## 交互与传输

- 浏览器提交后立即显示用户消息，回答经真实模型流逐段出现；连接、查记录、生成预览仅显示一行状态。
- `/api/ai/coach` 通过 Accept 协商 NDJSON；未请求流的既有调用保留完整 JSON。
- 继续使用 AI SDK 7.0.140 的 `ToolLoopAgent`，没有新写入通道或自建模型循环。
- `finish_response` 先生成来源 ID，再生成回答。服务端核对来源后只解码回答字符串，过滤原始工具参数和推理。其他字段顺序仍能得到完整回复，但没有提前显示的保证。
- 补录和计划只在工具参数与业务规则完整校验后通过终态返回；部分 JSON 永远不会生成确认按钮。批准、幂等执行、版本校验和回执沿用原账本。
- 必须收到正确请求 ID 的终态并正常结束传输才能完成。超时、停止、断流及异常丢弃临时回答，不进入后续六轮历史。重新提问使用新请求 ID；不会自动重试或执行写入。
- 请求取消传到模型；若取消前已保存待批准预览，仍可从账户恢复，当前计划不会因此改变。

## 首次进入

浏览器识别到已登录用户后，Agent 输入框即可显示，不等待资料与全量历史数据。真实数据仍由鉴权 API 读取；页面中的本地 session 不是服务端权限凭证。不同账号会重建对话，并清空旧账号的历史缓存，迟到的缓存响应不能覆盖新账号。

公开的模型可用性随路由传入，去掉 GET 状态再读取本地同意记录的串行等待。登录后在首页初始化期间提前预取 Agent；无跨账户业务数据缓存。

## 验证与边界

新增真实 HTTP 分块浏览器覆盖：首段早于完成、停止与断流、未验证来源过滤、页面切换、资料加载被阻塞时仍可提问、部分计划无确认入口。完整计划批准/回滚/幂等/账户隔离回归继续运行。

`scripts/eval-coach-stream.ts` 是显式启用、限定本地合成数据库的真实提供方评估。首轮四个场景通过：聊天首段 1.79 秒 / 完成 3.00 秒，双主题查询 2.35 秒 / 3.03 秒，身体草稿 1.47 秒，训练预览 6.10 秒；后两者只显示完整可确认草稿。不是正式站延迟或并发测试。

正式站使用同一合成账号、浏览器、网络测量路由可用、首段可见和回答完成。发布前后的原始证据、精确 CI 提交、部署 SHA、真实确认写入以及清理校验保存在发布交接。小样本不代表 P95、国内网络或物理手机。

记忆范围仍为页面内最近六个完整轮次，结构化记录与计划账本按账户持久保存。没有增加通用长期记忆、向量库、工具写并发或数据库权限。
