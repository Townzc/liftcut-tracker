# 90 秒演示：手机端记录、同步、更正、复盘与进阶

视频：[`evidence/demo-90s/demo-90s.webm`](evidence/demo-90s/demo-90s.webm)（约 74 秒，390 × 844，VP9）；最后一帧：[`next-target.png`](evidence/demo-90s/next-target.png)。

画面是 Expo App 的网页导出，连真实的 Next.js API、PostgreSQL 和本地认证替身；账号和数据全是合成的。教练的复盘回答来自脚本替身（`tests/product-browser/model-fixture.ts`），不是模型输出，画面开头的字幕写明了这一点。

## 重新录制

先按移动端端到端测试的方式准备（W1b 构建、App 网页导出、本地 `postgres:16`），然后：

```bash
W1B_TEST_DATABASE_URL=… W1B_RUNTIME_DATABASE_URL=… P1_BROWSER_EXECUTABLE=… \
  npx playwright test --config playwright.demo.config.ts
```

脚本是 `tests/demo/demo-90s.spec.ts`：它用 Chrome 的屏幕录制接口逐帧采集（按真实时间间隔），再用系统的 `ffmpeg`（需要 libvpx-vp9）编码成 WebM；不依赖 Playwright 自带的视频组件。每一步都有断言，流程不对就会失败，不会录出错误的视频。录制不在 CI 里运行。

## 边界

- 网页导出不是真机：通知、震动、常亮和原生 SQLite 不在画面里（见 `MOBILE.md`）。
- 复盘建议是脚本回答；真实模型的复盘质量见 M2-5 的回放评测（模型录制尚未运行）。
