# 云端 Claude Code 持续开发说明

给在云端长时间运行的 Claude Code 会话使用。维护者每周约 10 小时，只做关键决策；你按下面的任务队列持续实现、验证、合并。

## 每次开工先读

1. `AGENTS.md`（授权范围、合并阻断规则）
2. [手机 App + Agent 方案](2026-10-18-mobile-agent-plan.md)
3. [展品方案](2026-10-13-showcase-plan.md) 第 2 节规则
4. [产品日志](PRODUCT_LOG.md) 最上面 3 条
5. 写 Next.js 代码前，读 `node_modules/next/dist/docs/` 里的相关指南

不要读研究历史（`docs/research/`、`research/liftcut-agent/`），除非任务明确涉及。

## 运行环境的限制（先了解，别绕）

- 云端会话只能通过 HTTPS（443 端口）代理访问外网：**不能 SSH，不能直连远程 PostgreSQL**，WebSocket 和非 443 端口也不行。遇到这类需求，按下文的“交接”处理，不要尝试绕过代理。
- 数据库测试用 Docker 起本地 `postgres:16`（与 CI 相同）。起不来时写“本地未运行，依赖 CI”。
- 需要调用 DeepSeek 时，密钥由维护者配置为云端环境的网络密钥（只对 `api.deepseek.com` 生效，你看不到明文）。没有配置时，相关步骤写“未运行”，并在会话里提醒维护者。
- Linux 云端不能用 Xcode；iOS 只做到类型检查和 JS 打包验证。

## 工作方式

- **一个任务一个分支一个 PR**，基于最新 `main`。有效改动大约 400 行以内，超过就拆。
- **合并**：CI 全部通过后自行 squash 合并到 `main`。合并即触发生产部署；合并后确认部署成功，如果能访问正式站，再做一次只读冒烟检查。
- **生产迁移**：云端无法直连生产数据库。需要迁移时，PR 里附带迁移文件、备份和核验步骤，写进 `docs/product/PENDING_PRODUCTION_STEPS.md`，并在会话里告诉维护者；**依赖该迁移的代码必须带功能开关，迁移完成前保持关闭**，这样合并不会弄坏线上。
- **先问再做**：破坏性 schema 或数据变更、新的付费服务或账号、生产密钥、任何花钱的操作。
- 不从 opengym（AGPL-3.0）复制任何代码、文案、图标或素材；参考其设计时在 PR 描述写“仅参考设计”。
- 不提交真实健康数据、密钥或模型权重；测试和演示只用合成数据。

## 每个 PR 必须包含

- 改了什么、为什么（对应方案哪一节）。
- 实际运行的命令和结果摘要：`npm run lint`、`npm test`、`npm run build`，涉及数据库时运行对应的 PostgreSQL 测试，涉及界面时跑相关 Playwright 场景并附手机宽度截图。**没跑的检查写“未运行”，不能写成通过。**
- [产品日志](PRODUCT_LOG.md) 新增一条，不超过 15 行。

## 任务队列（按顺序）

### M0 — 共享核心与训练体验

1. **M0-1 单仓库**：npm workspaces，新建 `packages/core`，先迁移 Zod schema 与契约类型；网页改为从这里引用，行为不变，全部现有测试和 CI 通过。
2. **M0-2 迁移解析器与动作目录**：规则解析器、150 条解析评测、60 个动作目录迁入 `packages/core`；评测继续在 CI 运行，编造次数为 0。
3. **M0-3 进阶引擎**：`packages/core/progression`，线性、双重进阶、计时三种策略和连续失败减载。纯函数，只用用户确认过的实际值；未完成或未知的组算“未达成”。结果附中英文“为什么”。测试覆盖未知值、跳过、减载、kg/lb、自重、超过 12 次。
4. **M0-4 估算 1RM**：只用确认过的实际值，超过 12 次不估，返回所用那一组；历史页显示。
5. **M0-5 训练页体验**：完成一组后自动开始组间计时；训练中屏幕常亮（不支持时静默降级）；本组破纪录提示；动作卡显示进阶引擎给出的下次目标和“为什么”。
6. **M0-6 PWA**：Web App Manifest 和只缓存应用外壳的 Service Worker，不缓存用户数据或 API 响应；验证不影响离线发件箱和登录。

### M1 — Expo App

7. **M1-1 手机端认证**：API 同时支持 Cookie 和 `Authorization: Bearer <Supabase 访问令牌>`，服务端校验令牌；补跨用户访问测试。
8. **M1-2 App 骨架**：`apps/mobile`（Expo、TypeScript、expo-router），登录、中英双语、黑白主题，引用 `packages/core`。
9. **M1-3 今日训练**：处方、上次预填、点按完成、跳过、撤销、结束；组间计时本地通知；屏幕常亮；震动反馈。
10. **M1-4 离线**：SQLite 发件箱，沿用客户端 UUID、顺序补发、冲突暂停语义；断网冷启动可以记录。
11. **M1-5 一句话记录**：复用规则解析器；联网时可走现有服务端补录；确认卡与回执和网页一致。
12. **M1-6 构建配置**：EAS Build 配置（开发版、安卓内部测试版），步骤写进 `docs/product/MOBILE.md`。实际构建需要维护者的 Expo 账号，到这一步在会话里问维护者。

### M4（前半）— 端侧解析模型的数据、评测与训练准备

代码放在新目录 `research/m4-parser/`，与冻结的研究代码分开；不修改 `research/liftcut-agent/`。

13. **M4-1 数据规格与合成**：**先生成结构化标签，再生成句子**（不要让模型给句子打标签）。标签覆盖：多组、部分 RPE、kg/lb/公斤/磅、自重、跳过、结束、更正、“同上”、中英混杂、口语数字，以及应该追问的含糊句。句子由模板生成，可选用 DeepSeek 改写；改写后必须通过确定性校验（句中出现的数字与标签一致、单位一致），不通过就丢弃。现有 150 条评测与另外人工编写的测试集**只做评测，绝不进入训练**。写数据卡：来源、数量、分布、过滤率。
14. **M4-2 评测工具**：`packages/core` 里的统一评测，能评规则解析器、云端模型、端侧模型的输出文件。指标：字段准确率、**编造次数**（标准为空却给了值）、遗漏率、更正定位准确率、追问的精确率和召回率、JSON 合法率、延迟。
15. **M4-3 基线**：在开发集和测试集上跑规则解析器和 DeepSeek（需要网络密钥），结果入库。
16. **M4-4 训练包**：基座 Qwen3-0.6B（核实许可证并写进说明），固定随机种子的 SFT 脚本、评测脚本、导出 GGUF 量化模型的脚本、量化前后输出一致性检查。一个入口 `research/m4-parser/run_all.sh`：环境检查 → 训练 → 评测 → 导出 → 一致性检查 → 只把指标和文件哈希写入结果目录；有总时长上限，超时自动停止。先在 CPU 上用极小数据跑通全流程（冒烟测试）。
17. **M4-5 GPU 交接**：写 `docs/product/M4_GPU_HANDOFF.md`，内容见下一节；然后在会话里告诉维护者“可以开服务器了”，并继续做后面的任务，不要空等。

### M2 — App 内 Agent

### M4（后半）— 端侧集成（GPU 训练结果回来之后）

## M4 GPU 交接（第 17 步要写的内容）

云端会话不能 SSH，所以 GPU 训练由维护者开服务器后执行，二选一：

- **方式 A（推荐）**：维护者在自己电脑上开一个本地 Claude Code 会话（本地会话有完整网络，可以 SSH），让它读 `docs/product/M4_GPU_HANDOFF.md` 并执行。
- **方式 B**：维护者 SSH 登录服务器，复制交接文档里的一条命令运行。

交接文档必须包含：

1. 服务器要求（显卡、显存、磁盘、预计时长和费用上限）。
2. 国内网络下获取基座模型的方法（例如 ModelScope 或镜像），以及要核对的文件哈希。
3. 一条命令：拉取指定提交 → 安装依赖 → `run_all.sh`。
4. 结果如何带回：指标 JSON 和哈希提交到一个新分支；**模型权重不入库**，暂存服务器数据盘，等维护者决定托管位置。
5. 完成后提醒维护者关机，并记录实际用时。
6. 失败时保留日志，不自动重试超过一次。

## 遇到以下情况，在会话里问维护者

- 需要破坏性 schema 或数据变更、新的付费服务或账号、生产密钥、花钱的操作。
- 需要维护者的账号（Expo、Apple）、服务器或真机测量。
- 方案与现有代码冲突，处理方式会改变用户可见的行为或数据语义。
- 同一个 CI 失败修了两次仍未通过；或任务比预估大一倍以上。

提问时写清楚问题、证据、两三个方案和你的建议。等待期间继续做队列里不受影响的任务。
