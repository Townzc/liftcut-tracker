# 云端 Claude Code 持续开发说明

给在云端长时间运行的 Claude Code 会话使用。维护者每周约 10 小时，只做决策和审查；你负责按下面的任务队列持续实现。

## 每次开工先读

1. `AGENTS.md`
2. [手机 App + Agent 方案](2026-10-18-mobile-agent-plan.md)（本阶段的依据）
3. [展品方案](2026-10-13-showcase-plan.md) 第 2 节规则（合并阻断项）
4. [产品日志](PRODUCT_LOG.md) 最上面 3 条，了解最近做了什么
5. 写 Next.js 代码前，读 `node_modules/next/dist/docs/` 里的相关指南

不要读研究历史（`docs/research/`、`research/`），除非任务明确涉及。

## 工作方式

- **一个任务一个分支一个 PR**，基于最新 `main`。PR 要小到维护者一小时内能审完：大约 400 行以内的有效改动，超过就拆。
- **不合并、不部署、不执行生产迁移、不改生产环境变量、不租 GPU**。PR 开成草稿，CI 全部通过后改为可审查，然后进入下一个任务。
- 下一个任务依赖未合并的 PR 时，基于那个 PR 的分支继续，并在 PR 描述里写明依赖关系。
- **不从 opengym（AGPL-3.0）复制任何代码、文案、图标或素材。** 参考了它的设计时，在 PR 描述里写“仅参考设计”。
- 不提交真实健康数据、密钥或模型权重；演示和测试只用合成数据。

## 每个 PR 必须包含

- 修改了什么、为什么（对应方案里的哪一节）。
- 实际运行的命令和结果摘要：`npm run lint`、`npm test`、`npm run build`，涉及数据库时运行对应的 PostgreSQL 测试。环境里起不来 PostgreSQL 时写“本地未运行，依赖 CI”，**没跑的检查不能写成通过**。
- 有界面变化时附手机宽度截图（Playwright 可用）。
- [产品日志](PRODUCT_LOG.md) 新增一条，不超过 15 行：原因、实现、实际运行、局限、下一步。

## 任务队列（按顺序）

### M0 — 共享核心与训练体验（不依赖任何待定决策）

1. **M0-1 单仓库**：引入 npm workspaces，新建 `packages/core`，先只迁移 Zod schema 与契约类型，网页改为从这里引用。行为不变，全部现有测试通过，CI 不需要改动以外的配置。
2. **M0-2 迁移解析器与动作目录**：把规则解析器、150 条解析评测、60 个动作目录迁入 `packages/core`；评测仍在 CI 运行，编造次数必须为 0。
3. **M0-3 进阶引擎**：在 `packages/core/progression` 实现线性、双重进阶、计时三种策略和连续失败减载。纯函数，输入只用用户确认过的实际值；未完成或未知的组一律算“未达成”。每个结果附“为什么”文本（中英文）。单元测试覆盖：未知值、跳过的组、减载、kg/lb、自重动作、超过 12 次。
4. **M0-4 估算 1RM**：只用确认过的实际值，超过 12 次不估，返回所用的那一组。在历史页显示。
5. **M0-5 训练页体验**：今日训练页完成一组后自动开始组间计时；训练进行中屏幕常亮（Wake Lock，不支持时静默降级）；本组超过历史最好时提示。进阶引擎给出的下次目标显示在动作卡上，可展开看“为什么”。
6. **M0-6 PWA**：添加 Web App Manifest 和只缓存应用外壳的 Service Worker；不缓存任何用户数据或 API 响应。验证不影响现有离线发件箱和登录流程。

### M1 — Expo App（需要维护者确认第 8 节决策 1 后才开始）

7. **M1-1 手机端认证接口**：现有 API 同时支持 Cookie 和 `Authorization: Bearer <Supabase 访问令牌>`；用令牌在服务端校验用户。补跨用户访问测试。
8. **M1-2 App 骨架**：`apps/mobile`（Expo、TypeScript、expo-router），登录、中英双语、黑白主题，引用 `packages/core`。
9. **M1-3 今日训练**：处方、上次预填、点按完成、跳过、撤销、结束；组间计时本地通知；屏幕常亮；震动反馈。
10. **M1-4 离线**：SQLite 发件箱，沿用客户端 UUID、顺序补发、冲突暂停语义；断网冷启动可以记录。
11. **M1-5 一句话记录**：复用规则解析器；联网时可走现有服务端补录；确认卡与回执和网页一致。
12. **M1-6 构建配置**：EAS Build 配置（开发版、内部测试版）；把构建和安装步骤写进 `docs/product/MOBILE.md`。实际构建需要维护者的 Expo 和 Apple 账号，你只准备配置并写明。

### M2 及以后

完成 M1 后，按方案第 4 节 M2、M3 继续拆任务，先在 PR 里提交拆分清单让维护者确认。M4（端侧蒸馏）和语音输入必须等维护者明确开启。

## 遇到以下情况，停下来问维护者

- 需要改数据库 schema 中已有的列或删除数据。
- 需要新的第三方付费服务、账号或密钥。
- 方案与现有代码冲突，而冲突的处理会改变用户可见的行为或数据语义。
- 同一个 CI 失败修了两次仍未通过。
- 任务比预估大一倍以上。

提问时写清楚：问题是什么、你看到的证据、两三个可选方案和你的建议。在等待回答期间，可以继续做队列里不受影响的下一个任务。
