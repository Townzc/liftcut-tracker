# Agent 对话计划：生成、调整与批准

2026-10-14。承接 [产品规划](2026-10-13-showcase-plan.md) 和 [开放对话](MODEL_CONVERSATION_BRIEF.md)。

后续首屏与流式回复改进见 [AGENT_STREAMING_BRIEF.md](AGENT_STREAMING_BRIEF.md)；本文的非流式指标保留为当时的验证记录。

## 用户流程

在 Agent 中描述训练条件或饮食目标，得到完整预览；继续说出修改要求即可调整。卡片展示各天安排、替换对象、变化与估算标识。用户点击“确认并应用”后，服务器批准并执行；聊天里的“好”“确认”不会执行写入。修改后的预览必须重新确认。生成与确认不会新增实际饮食、体测或已完成训练记录。

最近五个预览和回执可从账户恢复，刷新后可继续确认或放弃。这个数量是界面读取上限，不是数据库保留上限。旧预览、设置或当前计划发生变化时，服务器拒绝过期执行；丢响应后可查询回执并以同一操作键重试。当前已开始的训练保持其会话快照。

Agent 默认只显示对话。说“开始训练”才显示训练日选择，说“查看回执”才显示记录、撤销与计划历史；确认计划后立即更新可选训练日。首次启用模型需明确同意，之后对话选项收进右上角按钮。首页移除聊天跳转框及快捷提问，保留手动补录并使用英文句点。设置改为黑白分组列表，账号、训练饮食偏好、外观语言、数据与说明分别进入独立页面。

## 工具边界

模型共有十个工具，按当前阶段只开放必要子集：

| 工具 | 权限与用途 |
| --- | --- |
| `read_records` | 本人身体、实际饮食、训练和饮食计划；日期范围有上限，可批量读取三个主题 |
| `current_workout` | 本人当前训练会话及实际组数 |
| `prepare_body`、`prepare_food`、`prepare_workout` | 产生待确认补录，不直接保存 |
| `plan_context` | 读取本人设置、当前计划或选定预览，以及版本绑定 |
| `prepare_training_plan`、`prepare_nutrition_plan` | 校验并保存不可变的待批准预览，不更改当前计划 |
| `prepare_plan_adjustment` | 对可验证的原计划应用白名单字段变更，其余内容由代码原样保留 |
| `finish_response` | 返回回答及本次读取的来源 |

批准、执行、SQL、删除数据和跨账户读取不在模型工具中。业务写入由已有批准账本控制；事务内检查用户、内容哈希、设置与活动计划版本、批准 ID 和幂等键。训练与饮食使用相同的每用户锁；兼容旧页面的计划写入也参加该锁。

## 延迟与并发

独立主题在一次 `read_records` 中并行查询，同请求相同范围复用 Promise；缓存不跨请求或账户。小修改发送字段补丁，不重写整份计划。工具菜单按阶段收窄，减少无关 schema；有效预览直接结束模型循环，省去结尾生成。普通回答与计划输出使用不同长度预算。

底部三个主入口启用完整路由预取，并提供加载边界。Agent 输入框不再等待训练数据；训练加载失败也不应阻止独立的身体/饮食补录。服务端鉴权和版本校验保持执行，未用共享用户数据缓存换取速度。设置首页使用独立的轻量菜单组件。

有依赖的工具仍顺序执行：先读取计划，再产生预览。批准与执行按用户序列化，避免并发覆盖。每个运行时数据库连接池最多四个连接，使用 Supabase 事务连接池及验证证书的 TLS。不能把调高模型工具并发数当成整个链路加速，也不据此声称承受了某个并发用户数。

真实 DeepSeek Flash + 本地合成数据库的第二轮八次验证全部通过：新训练和新饮食模型阶段分别 4.90 / 5.06 秒；四次局部调整为 1.97–2.95 秒；双主题查询 2.40 秒。每次两步。此为小样本模型阶段观测，不是正式网站端到端延迟、P95 或负载测试。首轮八次也通过；未进行模型间性能对比、流式输出或并发压测。

## 记忆与隐私

聊天文本只保留页面内最近六轮、最多十二条历史消息；离开、刷新、关闭或清空后丢弃。每次查询都重新读本人数据，旧助手回复不能作为新事实。结构化个人设置、实际记录、计划、预览与回执保存在账户中，清空聊天不会删除这些业务数据。模型仅接收本次需要的内容，不接收连接凭据、内部账户标识或跨账户数据。

没有通用长期记忆、向量库、自动偏好提取或跨对话自由文本检索。未来若需要“记住我的偏好”，应设计有明确确认与删除入口的结构化设置变更。

## 验证与发布边界

本地实际运行：93 个单元测试、47 个产品数据库测试、32 个既有批准账本数据库测试、49 个浏览器场景；构建/类型检查通过，lint 零错误、两条既有研究警告。浏览器套件使用真实 Next.js/API/PostgreSQL 和脚本化模型/Auth 替身；真实模型另有两轮共 16 次合成验证。覆盖预览无业务写入、双击/丢响应重试、事务回滚、过期内容、跨账户拒绝、重新批准及饮食目标不计入实际。

证据目录：[verification.json](evidence/coach-plans/verification.json)。正式域名发布、远端迁移、真实 Auth/模型浏览器验收与账号清理在发布交接单独记录，不能由本地测试推定。尚未做物理手机、并发压测或对任意自然语言的正确性保证。
