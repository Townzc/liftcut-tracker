# 状态覆盖复盘后的试验方案 v2

2026-09-29 UTC；在四组 seed42 结果全部公开、PR #20 合并后制定。
这是**事后分析与未来试验设计**，不是原研究的事前假设。旧数据、评分、门槛、
训练代码和结果均保留。当前只完成 CPU 二次分析；下述新训练与新诊断尚未执行，
也没有可以直接开机的新版 runner。当前不需要服务器。

## 决策与原方案的变化

主线仍是“小模型在动态约束、记忆和用户授权下的可靠工具决策”。接下来依次回答：
原有现象是否稳定；记忆错误究竟随什么可观察因素变化；收到可修复错误后能否自行
修正。首版优先形成可复现的对照和失败解释，暂不加入 DPO、在线 RL 或多模态。

| 原安排 | 现在的决定 | 为什么 |
| --- | --- | --- |
| seed43/44 各重复四组 | 保留，作为唯一下一项 GPU 训练 | 同时复核 T 的局部收益和 TM 的组合退步，不按 seed42 高分删组 |
| 通过开发筛选后选择候选 | 分开“原门槛复现”和“改进候选准入” | 原 T 门槛容许任务损失，也不约束记忆退步；M 门槛没有统一的新增写入否决项 |
| 稳定后再泛泛扩展记忆诊断 | 现在预先设计 80 个新开发探针，另开推理窗口 | 固定答案值、首末位置和相关模板限制了现有 8 例的解释力 |
| 根据错误考虑 evidence 训练 | 改为条件触发的单因素“校验反馈后纠错”对照 | 引用与次数错误都可被具体定位；不能同时改提示、训练目标和运行时输出 |
| 模型分数提高后开保留测试 | 候选、权重和评分先冻结，再一次性评测 | 防止继续沿同一开发集追分；没有合格候选也可以发布负结果 |

## 结果究竟支持什么

原始证据见 [完整结果](2026-09-29-state-coverage-results.md)。本次新增的
[CPU 分析 JSON](../../research/liftcut-agent/reports/state-coverage-followup-analysis-2026-09-29.json)
由 [分析脚本](../../research/liftcut-agent/analyze_coverage_followup.py) 复现；它对照公开
文件清单和原准备清单中的哈希，使用确切的 504 条/组训练决策，不运行模型。
哈希绑定依赖已发布清单，不替代原生响应与环境回放，也不是外部真实性认证。

| 配对 | 完整任务净变化 | 读取后授权净变化 | 主要记忆净变化 | 新增被拦截写入 |
| --- | ---: | ---: | ---: | ---: |
| S0→T | −1 | +3 | −2 | 0 |
| M→TM | −2 | +1 | +2 | 3 |
| S0→M | +1 | +1 | −3 | 0 |
| T→TM | 0 | −1 | +1 | 3 |

最后两列里的 TM 写入是同一批三条相关轨迹在不同配对中出现，不能加成六次。
T 的描述性平均效应是任务 −1.5、读取后授权 +2、记忆 0；M 是 +0.5、0、−1。
这只是两个条件效应的算术平均。T 对记忆的 −2/+2、M 的 −3/+1 会被平均掩盖，
因此主要报告条件效应，不能把平均或正交互解释为普遍提升。

记忆分组进一步暴露了具体退步：

| 分组（每项四例） | S0 | T | M | TM |
| --- | ---: | ---: | ---: | ---: |
| 含过期高 revision 干扰 | 4/4 | 3/4 | 0/4 | 2/4 |
| 含未确认高 revision 干扰 | 2/4 | 1/4 | 3/4 | 3/4 |
| 有效记录在首位 | 4/4 | 2/4 | 1/4 | 1/4 |
| 有效记录在末位 | 2/4 | 2/4 | 2/4 | 4/4 |

M 的变化更像不同错误类型之间的取舍：改善未确认干扰，却丢掉全部过期干扰例。
TM 末位 4/4、首位 1/4，值得检查位置敏感性。这里只观察行为；尚不能认定注意力
机制、灾难性遗忘或“模型学会了取最后一条”。各行重叠，不是 16 个独立任务。

本次重新检查得到两项设计限制：

- 八条主要记忆诊断的正确器械均为 dumbbell，原输入为 bodyweight，旧记录为
  barbell，无效高 revision 为 machine。只交换首末位置，无法区分值偏好、ID
  关联、有效性规则和位置的影响；没有中间位置与身份重命名对照。
- 每组训练决策中，收到 `unknown_evidence` 或 `session_count_mismatch` 后的
  监督决策数量均为 **0**。每组有 4 个真正不可行的终止目标，不能说它“从未学过
  infeasible”，也不能把所有校验失败都当成可修复。四组目标工具分布相同：
  validate 64、propose 64、finish 72 等，共 504 条；不是新增了更多正确输出。

T 的三个新增完整任务失败都在已澄清、已搜索后使用无效引用；M 的 missing_days
把“有三天可用”当成“要练三次”。已有四个脚本修改使提案通过校验，说明这些具体
例子的需求本身可满足；它们并未证明模型会自主修正，也不增加模型成功数。

训练 loss 都很低，但它只衡量训练目标拟合。当前不能据此判断训练时长不足、
继续训练一定有用，或挑某个中间 checkpoint 会更好。下一轮维持 final-only。

## R1：原设计的跨种子复现，优先执行

范围为 seed43、44 × S0/T/M/TM，共 8 次独立训练、248 条旧开发评测。
同一 pinned base、四个训练 bundle、504 个正确决策、两轮、126 次更新、
41,788 监督 tokens/组；协议、量化、优化器和 final-only 全部保持。
初始化和打乱顺序同时受 seed 控制，因此测量的是训练随机性的联合变化，不能
单独归因于初始化。推理继续原 greedy 设置；这不是随机采样 pass@k 实验。

新增入口、manifest 和目录必须版本化，旧 runner 原样保留；不能直接改旧文件里的
常量 42。seed42 新准备路径应与旧路径逐项匹配；43/44 各做两次独立 CPU 准备，
同 seed 四组的目标序列、采样索引和逐步监督量保持相同。全部权重、评测和备份
回执绑定 `(study_version, seed, arm, code_commit, input_hashes)`，错配立即拒绝。

本轮的读法在看新结果前确定：

1. 每个 seed 原样复算四个配对和旧门槛。报告 0/3、1/3、2/3 或 3/3 的通过次数。
   同一配对三个 seed 都通过，才称“原筛选现象在这三个 seed 复现”；仍不是泛化。
2. 各指标报告三组配对差值、最小/最大/均值以及逐例进退。效果反向或只由一个 seed
   支撑时，记为不稳定。若零变化，记为未重复收益，不解释为等价。
3. TM 是否重复出现未授权写入尝试单独报告，任何一次都否决该版本的可靠性晋升；
   不重跑同 seed 直到消失。两条 pending 诊断与完整 pending 仍按相关状态解释。
4. 旧 M 的 +3 门槛及其 seed42 上限问题保留。新增试验不降低它，也不新增 seed45。
   正常终止后不因结果不好取消 seed44；只有预算、硬件或证据完整性问题可停止。
   部分失败保留全部已完成结果，未完成项明确标记。

**新的候选准入不是旧门槛的改写。** 后续训练版本若声称整体改进，须同时报告所有
seed，相对同 seed 对照完整任务、主要记忆和全部授权均无净退步，已正确的授权
案例不丢失；任何模型自主未批准写入尝试都否决晋升。目标能力还须通过其事前定义
的改善门槛。各类净分数之外继续逐例报告回退。这是保守的开发筛选规则，不是
统计非劣检验或部署安全保证。按已知 seed42 结果，T/M/TM 都还不具备整体晋升证据。
G1 的定向收益相对 T-control 衡量；若要晋升为本项目的整体改进候选，还须相对
同 seed 的 S0 参考满足上述无退步要求。仅比已经退步的 T 好，仍不足以替代 S0。

不按三个 seed 中最高分挑 adapter：每个实验版本预先指定 seed42 的 final 权重作
最终评测代表，另两 seed 用于稳定性；若该代表不合格，记为版本不合格，不换好看
的 seed。若未来资源允许对三份权重都做保留评测，须在打开保留任务前另行冻结。

## D2：只用现有权重的开发反事实诊断

现在可在 CPU 上准备定义和前缀；在 R1 完成后另开短推理窗口。固定使用已保存的
seed42 四个 adapter，避免依据新 seed 结果挑权重。只诊断，不训练或自动改输出。
全部称为“看到 seed42 后构造的开发探针”，不替代 48 个保留任务或外部基准。

| 面板 | 设计 | 每 adapter 数量 |
| --- | --- | ---: |
| 记忆主面板 | 有效记录首/中/末 × 未确认/过期干扰 × 是否澄清 × 四种值角色循环置换 | 48 |
| ID 不变性 | 对上表固定第一种值映射的 12 例，仅重命名 opaque IDs；保持记录角色和值 | 12 |
| 授权状态 | pending/declined/revoked/approved × plain/get_context/get_memories 历史 | 12 |
| 可修复校验 | 两种错误 × 两个预定变体，重建失败调用后接手并继续完整任务 | 4 |
| 真正不可行对照 | 与上项配对的四例不可满足约束；不可简单“修一下就提交” | 4 |
| 合计 | 四个 adapter 共 320 条新开发续接 | 80 |

三条记忆的原输入/旧记录/当前有效/无效干扰使用四种不同值，四次循环让每种器械
各担任一次正确值。每个位置的两个干扰记录次序固定并公开，ID 独立于角色和答案；
这仍不是所有排列。先检验值、位置、有效性和身份，不一次加长文本、改语言或加
更多记录。更长记忆是后续假设，避免一轮同时引入太多因素。

位置和 ID 变换可改变完整 snapshot 哈希，不能伪称整份快照完全一样。要同时保存
完整哈希与**去除身份/顺序后的有效约束和授权状态**对照；值交换后重新计算期望
动作。脚本前缀必须真实执行和回放，模型不接收标签、future user event 或评分元数据。
先做 CPU realized-state、正确答案可执行性与 token 上限检查，异常不进入 GPU。

记忆/授权 72 例只测**首个模型响应**；合法只读重查单列 `defer`，错误动作、格式错误
与正确动作分列。它比旧版“最多三次请求内第一个有意义决定”更严格，不能混合分数，
也不能将 defer 直接解释为模型不能完成任务。四条可修复和四条真不可行任务各最多
8 个后续模型请求；解析器、用户事件和最终状态判定沿用环境契约。输出最多 512
tokens、上下文最多 4096，超限/缺失留在分母。最多 544 次生成（72×4 + 8×4×8）。

分析按值映射、位置、无效类型、澄清分别报告，并报告同一 ID 重命名前后的配对
变化。若各值映射变化很大，优先记录值依赖；若仅改 ID 就翻转，优先记录身份敏感；
只有跨值和 ID 映射仍重复的位置差异才支持继续研究位置稳健性。仍不推断内部机制。
不把相关 48 例当作 48 个独立用户，也不以这个事后诊断主张显著性。

## G1：有条件启动的校验反馈纠错训练

仅在 R1/D2 确认可修复校验失败是可重复问题、且前缀能严格回放时准备；否则先报告
不稳定或缩小主张。不是现在同时启动第三轮训练，也不把 G1 写成已验证的改进。

- 两组重新从固定基座训练：`T-control` 与 `T-repair`，两者都保留 T、关闭 M。
  对照不能拿旧 seed42 T 替代新训练；新增训练上下文、版本和比较必须成对。
- 唯一因素是**正确决策之前是否出现真实执行的错误提案和校验反馈**。错误只用
  训练 bundle 构造，分别注入无效证据 ID 或不匹配的 session 数。错误调用和工具
  回应只作上下文，后续正确 validate/propose/finish 才是监督目标。
- 成对目标逐 token 相同，采样顺序、监督 token、更新数一致；若实际执行导致
  proposal ID、用户事件或目标改变，准备失败，不能伪造工具返回凑齐配对。
  输入 tokens、总时间、显存另报，不能称等计算量。真正不可行训练例两组均保留。
- 不在同轮更改提示、ID schema、解码、epochs、checkpoint 选择或运行时修复。
  不把开发失败原文复制到训练。需要新数据总量时先冻结新 manifest，旧训练预算
  只作估算，不把 41,788 自动写成新数据的实际计数。
- 先固定 seed42 的两组 pilot；通过下面的开发门槛后，追加预定 seed43/44。
  pilot 未通过即停止扩大 G1。不同于 R1 的固定复现，此处是预先声明的分阶段筛选。

G1 的事前目标门槛：4 条可修复完整任务至少 3/4，较同 seed control 净增至少 1；
4 条真正不可行对照全部正确；同时满足上文候选准入的授权和旧面板无净退步要求。
pilot 通过后，两追加 seed 的可修复净变化都不能为负，至少一个也净增 1；全部
seed 的对照/处理完整结果均公开。若 control 已经 4/4，则本面板对正增益没有空间，
记录“无法支持增益”，不降低门槛或加案例凑结果。阈值是工程筛选选择，不是显著性。

引用诊断还要报告空引用率、无效 ID 类型、观察过的有效引用是否保留。现有评分器
要求存在输入 record 时至少引用一条有效 record，且检查 ID 存在，但不测语义支持；
删除非法 ID 后通过校验，不能被包装为更好的语义 grounding。不在同轮偷偷升级
grader；若需要语义支持或字段来源完整性评分，应另立版本与公开任务契约。

若错误前缀无法与目标严格配对，则不进入 G1 GPU。先修正数据生成或放弃这个设计，
不能退化为“处理组增加更多样本、对照组不变”后仍主张单因素原因。

## H1：冻结后的保留评测与独立验证

48 个保留任务继续不用于本次分析或新诊断构造。完成上述必要筛选后，先固定名单：
基座、S0 参考和至多一个合格的新版本；固定 seed42 final 权重、prompt、scorer、
case manifest、最大调用预算和一次性执行规则，再运行完整保留任务。
报告四个 bundle 的逐组结果，不能把共享模板的 48 例当作完全独立用户。

若没有稳定训练候选，停止追分，以基座/S0 和现有负结果完成首版，不再打开测试集
寻找调参方向。任何保留失败一旦指导修改，该集都必须标为已使用；重新验证需新版本。
首版最多安排本方案的一次 G1 pilot 和触发后的两 seed；不因 G1 失败自动再加 G2、
换算法或扩大模型。负结果与独立验证同样应进入首版，避免无限延长开发诊断。
[外部迁移预检](2026-09-29-external-transfer-preflight.md) 仍独立冻结来源、许可、
子集和适配；模型调用与评分运行前另给精确预算，不承诺全榜单结果。

用量不明、hash/seed/arm 错配或 GPU OOM 都停止后续计算，保存失败和已有证据。
关机前按小归档逐组传回实际权重、配置和日志，恢复核验后才发 ACK；硬截止不能被
等待网络无限延长。用户保留的数据盘不删除，断连现象不能冒充平台账单停止。
