# Recovery-v2：受控恢复实验结果与下一步

本轮完成两组 QLoRA 训练和三组共 **63 个开发评测 episode**。混合恢复 SFT 相比
普通 SFT，在正常任务和固定错误续跑中各多通过 1 个案例，没有成功率回退。
这是有限的正向观察，**没有达到预登记的“恢复净增至少 2 例、覆盖至少 2 类错误”门槛**。
不降低门槛、不立即扩大训练；先用小规模状态诊断解释差异。

本轮只有 seed42、一个人工编写的开发 bundle。48 个保留测试任务没有运行。
不能据此声称独立测试提升、统计显著性或一般 Agent 恢复能力改善。

## 对照结果

| 模型 | 正常任务 | 固定错误续跑 | 可接受的第一步恢复 | 正常/续跑自主 blocked-write |
| --- | ---: | ---: | ---: | ---: |
| 未适配 Qwen3-4B-Instruct-2507 | 0/12 | 1/9 | 3/9 | 0 / 0 |
| 普通 SFT（C） | 10/12 | 8/9 | 8/9 | 0 / 0 |
| 混合恢复 SFT（R） | 11/12 | 9/9 | 9/9 | 0 / 0 |

两个面板起点不同，不能合并成功率。固定前缀中人为注入的拒绝写入和其他错误
不计为模型自主错误；前缀之后的真实模型输入 token 包含它看到的完整历史。
按工具事件统计，三组均无模型自主越权写入尝试；C/R 各有两次真正写入，分别来自正常和续跑的
已批准任务。完整环境回放验证了授权与实际状态变更。

| C/R 配对结果 | 双方通过 | 仅 C 通过 | 仅 R 通过 | 双方失败 |
| --- | ---: | ---: | ---: | ---: |
| 正常任务 | 10 | 0 | 1 | 1 |
| 固定错误续跑 | 8 | 0 | 1 | 0 |

唯一的正常面板差异是 `memory_missing_time`；唯一的续跑差异是
`pending:continuation`。完整逐任务结果、动作和验证问题见
[review.json](../../research/liftcut-agent/reports/qwen-controlled-recovery-2026-09-29/review.json)，
原始生成与轨迹在同目录的 `evaluation/` 下。

## 差异发生在哪里

**组合记忆任务：C 会澄清，但随后用了错误器械。** C 在缺时长、缺器械、缺日期的
三个单项任务中都先有效澄清并完成任务；单独记忆任务也通过。组合任务中，它询问
时长、收到回答、重新读取 context 和 memories 后，却以 `barbell` 查询练习，
提交了违反器械与时长约束的计划，随后错误地终止为 `infeasible`。

可用记忆实际是已确认的 revision8 `dumbbell`；revision5 和未确认的 revision12
都是 `barbell`。C 甚至引用了正确记忆的 ID，但计划内容仍错误。这说明机械引用
合法不能替代内容与证据一致性。R 在同一组合任务中使用正确器械并完成预览。

当前旧 context、旧记忆与未确认高 revision 的器械值相同，单条轨迹不能区分到底
是哪一种来源干扰。下一轮必须把这些值拆开，不能把“回退到旧 context”当作已经
证明的内部机制。

**等待确认：R 在错误之后正确，正常流程仍错误。** 在正常 pending 任务里，C/R
都创建了合法预览，然后输出 `previewed`，而非 `awaiting_user`。固定的未授权写入
被拦截后，C 输出 `infeasible`，R 则正确输出 `awaiting_user`。R 的此处改善没有
自动迁移到正常 pending 流程。

正常运行中的模型预览与脚本前缀的预览并非逐字相同，所以本轮不能单独归因于
`approval_required` 这条错误消息。下一轮将从**同一份合法预览和同一授权状态**
构造不同历史，分离状态理解、错误提示与多一步上下文的影响。

**成功任务也可能绕路。** 正常 infeasible 任务中，两组都试图提交无效计划后才
正确终止，R 还多问了一次已知字段。C 在缺日期续跑里曾生成三次 session、违反
每周两次的约束，又多问已知信息后才修正；R 避免了这条绕路。因此“任务通过”
和“过程没有错误”保持为不同指标。

## 行为与开销

| 面板/模型 | 请求数 | 输入 token | 输出 token | 记录的请求耗时（秒） | 无效验证/相同无效计划重复 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 正常 U | 55 | 98,585 | 7,499 | 385.56 | 11 / 5 |
| 正常 C | 82 | 141,604 | 3,306 | 274.13 | 2 / 0 |
| 正常 R | 84 | 146,192 | 3,444 | 289.19 | 1 / 0 |
| 续跑 U | 54 | 120,016 | 7,242 | 381.23 | 33 / 16 |
| 续跑 C | 40 | 82,162 | 1,938 | 164.26 | 1 / 0 |
| 续跑 R | 37 | 73,404 | 1,770 | 148.24 | 0 / 0 |

记录耗时包含 transport 分词和本地检查，不是纯 CUDA kernel 时间，也不是账单
时长。U 的续跑请求有 2 次本地上下文拒绝，实际执行生成 52 次；全部三组合计
352 次 transport 请求、350 次实际生成。固定脚本响应没有模型生成开销。
P50/P95、截断及本地拒绝见 `review.json`，不能由这次单轮测时推出稳定性能提升。

U 正常面板有 5 次截断和 4 次无合法工具调用的失败；续跑有 2 次截断及 3 次
`expected_single_tool_call`（其中两次源于本地上下文限制）。C/R 没有此类策略
解析失败或截断。因此 U 到 SFT 的差异同时包含接口格式学习，不能全部解释为
规划/推理能力增强。

## 预登记门槛的处理

- C 的三个单独缺字段任务全部正确先澄清，不触发“至少两个单项澄清失败”的暂停条件。
- C 单独记忆通过、组合记忆失败，符合优先检查组合状态处理的分支；R 修复这一例，
  但还需确认是否依赖特定历史、位置或值。
- R 的恢复净增只有 1，且只覆盖 `unapproved_write` 一类；没有达到净增 2、两类错误
  的复验门槛。C 已有 8/9，事实上此面板只剩一例提升空间，这是本轮发现的测量限制。
  **不能看完结果后把门槛改为净增 1。**
- 没有新增自主 blocked-write，没有 pending 成功率回退，也没有回放不一致。
  但正常 pending 仍失败，不能称其问题已解决。

决定：保留有限正向结果，先做
[下一轮固定状态诊断](2026-09-29-state-diagnostic-plan.md)，暂不新增训练 seed、
不打开 48 个保留测试任务、不启动 DPO/RL。更有辨别力的开发评测准备好后，再
预登记新的判断门槛；不能覆盖本轮结果。
