## 问题与取舍

当前模型在干净工作流上较好，但在不改变业务状态的额外读取之后重启规划；记忆
位置与有效性存在训练相关性，来源值也缺少区分。因此下一轮先研究**监督数据中的
状态覆盖**。保留原提示词、工具协议、基模和推理参数，不同时引入提示词修复、
确定性记忆解析器或奖励优化，否则难以解释收益。

如果以后用代码直接选择有效记忆，那属于系统设计改进，应与模型自行选择分开。
本轮仍要求模型根据所有已公开事实判断，不能把 expected outcome、正确工具名或
选中的 memory ID 写进输入。环境继续独立强制写入授权。

## 拟采用的 2×2 对照

四组共用同一批新的、仅来自训练 bundle 的基础任务及相同正确目标。
公共基础任务让四种器械来源可区分；这意味着新研究与 v2 的绝对分数不能做单因素
归因。**只有下面四组之间的配对差异用于因素分析。**

| 组 | 预览后无状态变化的读取历史 T | 记忆位置与无效类型解耦 M |
| --- | --- | --- |
| S0 | 否 | 否 |
| T | 是 | 否 |
| M | 否 | 是 |
| TM | 是 | 是 |

- **T 因素：** 在部分正确终态目标之前加入真实执行的 get_context/get_memories。
  业务状态不变，正确 finish/apply 目标不变；额外读取只作为上下文，不增加被监督
  的正目标。所有历史必须实际执行和回放，不能拼接出不可能的授权状态。
- **M 因素：** 每个训练 bundle 都包含未确认和已过期两种高 revision；S0/T
  保留位置与无效类型的相关性，M/TM 在相同记录、值、revision 和目标下做平衡排列，
  使有效记录首/末与两种无效类型交叉覆盖。这样测试的是排列覆盖效果。
- **公共基础：** 原始 context、旧确认、当前有效、无效高 revision 四种值互异；
  在训练 bundle 间轮换对应关系。共同引入四来源值的收益不由上述 M 因素单独解释。
  若需要测其效果，另做有预算的独立消融，不临时加到四组结论中。

首轮只使用 seed42 筛查方向。LoRA、优化器、微批量、更新数沿用可核验设置；具体
样本数和 token 数在 CPU 导出后确定。必须逐个配对正确目标并验证真实 tokenizer
的 target token 一致，使用同一采样顺序和目标 token 归一化。额外输入长度、时间和
显存分别报告。做不到匹配就先修订设计，不能启动后才用总量近似掩盖差异。

公开 episode/proposal ID 只依赖当时可见事实，记忆排列应采用排序后的公共事实
生成身份，避免排列变化偷偷改动 proposal ID 和目标 token。不得引入未来用户状态。
这是新版本的身份规则；旧 v2 和已完成诊断的代码、数据、结果全部保持不变。

## 评测与停止标准

每组分别运行原 12 个正常开发任务和已冻结的 19 个状态诊断，不合并成功率。
本轮设计受这些开发结果启发，因此它们仍是反复使用的开发集，不称独立测试。

在看到新模型输出之前，CPU 准备报告须固定下列开发筛选门槛：

1. T 的定向效果：比较 S0→T 和 M→TM，至少一个配对比较在三个额外读取的确认
   状态中净改善至少两例，且不增加自主越权写入。
2. M 的定向效果：比较 S0→M 和 T→TM，至少一个比较在八个主要记忆状态中净
   改善至少三例，并包含至少一个记忆加澄清状态。纯澄清对照单列。
3. 正常任务相对各自无该因素的对照净损失不超过一例；报告所有退化，不通过汇总
   或只挑 TM 对 S0 掩盖交互作用。授权行为与原始格式失败逐项检查。
4. 以上只是开发筛选门槛，不是统计显著性。只有出现稳定方向，才估算 seed43/44
   的验证成本；否则继续分析或发布负结果，不追加大规模训练。

48 个保留任务仍不打开。候选、训练方案、推理配置和停止标准最终冻结后再进入
保留测试阶段；不同模板或外部数据的独立验证仍是首版缺口。

## 开机前必须完成

- 新版本训练场景、目标配对与 split/group 审计；不把 19 个开发诊断导出为训练。
- 每个变体可执行，额外读取前后业务状态等价；批准/拒绝反事实在用户事件前一致。
- 对每个 bundle 检查器械来源轮换及位置×有效性列联表，避免新的捷径相关性。
- 四组所有 target token、采样顺序、更新数匹配，输入长度无静默截断。
- 两次独立 CPU 准备一致；相关回放、预算与备份测试通过，分支 CI 完成并合并。
- 按实际 token 数、已有实测吞吐估计窗口；明确预算与关机安排后再通知开机。
