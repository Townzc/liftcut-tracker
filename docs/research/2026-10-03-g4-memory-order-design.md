# G4：在停止配方固定后，单独检验记忆排列覆盖

设计时间：2026-10-03 UTC，尚未启动G4 GPU工作。G3现已完成两组实际权重、222条
native/environment和376次生成token的本机恢复，stop_half满足停止机制但整体候选失败。
PR38最终五项检查通过后合并02069c4；该真实结果满足本方案事先约定的进入条件。

## 问题与假设

旧训练的记忆列表只有VOU/VUO/OXV/XOV四种排列。V是最新有效记录，O是较旧有效记录，
U/X分别是未确认/已过期的干扰记录。这使位置、有效性和revision比较混在一起；
G2的24个记忆错误全部落在旧有效值在前的未见排列。G3只动停止上下文也会改变记忆
成绩，说明当前策略还不稳。覆盖不足是可检验解释，不能仅凭相关性宣布是唯一根因。

假设：保持同一stop_half配方、目标和预算，单独解除训练中“位置×干扰类型”的绑定，
能提高最新有效记忆选择并保住已获得的停止/修复/授权行为。

## 两组与干预边界

- control：从同一固定基模新训完整G3 stop_half配方。历史G3只用于复现检查，正式
  效果比较使用本次新对照；即使新对照不复现旧分数，也保留它，不拿旧分数顶替。
- permuted：同一初始化、504个目标、1008次曝光、126步、41,788监督token、索引
  顺序和stop_half的四次错误后停止曝光；只改变已有记忆记录的列表顺序。

不是新增记忆记录、改正确答案、增加训练步数或继续训练旧adapter。32个记忆场景
包含memory与memory_missing_time各16个；每个类别的U/X各8个场景覆盖全部6种
排列，额外2个排列按固定规则轮换。所有记录ID、值、revision、有效性、split、
family和公开episode identity不变。全部clean/repair轨迹用真实环境重新执行并回放，
监督mask继续排除注入错误和上下文只读动作。非记忆轨迹不变，G3停止池原字节复用。

两次完整CPU准备：12种排列各2或3个场景，两个池各124/504条决策上下文改变；
每组最终1008次曝光中248处输入改变，两组输入总量均1,879,075 token、监督41,788 token，
最长3126。逐条差分只允许get_memories返回的列表顺序变化。CPU准备和合成合同演练
不代表模型收益；实际新权重、真实推理和云端运行仍待执行。

## 结果之后做什么

若全部门槛通过，优先冻结候选、准备重复seed与独立验证，今晚不把更多开发拟合
冒充泛化。若仍失败，停止盲目扩大相同SFT，把确定性最新有效记忆视图作为单独系统
对照，明确“系统解析帮助”与“模型学会选择”是两种贡献。任何第二小试验仍需先
保存其独立假设、输入协议、基线、指标和剩余时间，不能临时修改G4门槛。

学习检查：解释为什么“保持答案与token相同”仍可能产生完全不同的训练结果；
从一个真实get_memories返回手算最新有效记录；讲清新对照没有复现时该如何报告，
以及为何产品上把确定性规则交给代码不等于算法研究失败。
