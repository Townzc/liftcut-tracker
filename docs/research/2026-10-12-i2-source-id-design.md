## 为什么开展

记忆 11→42/48。但 ID 只有 6/12，低于原机制门槛 10 和固定 S0 的 7；候选仍失败。

## 两个因素具体做什么

N 按公开记录/记忆的完整内容（去掉原 ID，保留种类、值、revision、有效期等）
生成 `ev_` 加 12 位内容哈希别名。改名、列表重排和重复读取不改变同一证据的别名；
内容变化会改变别名。原始 ID 到别名的映射只存后端审计，不发给模型。
同义不同 ID、哈希冲突、ID 复用但内容变化等歧义直接拒绝，不能靠原 ID 或位置选边。

只转换记录/记忆字段和 plan.evidence_ids。模型新动作中的别名还原成原 ID，
再进入原环境。工具调用 ID、proposal ID、审批 revision、幂等键不转换。历史轨迹
里的错误证据 ID 保留给修复决策；新动作未知别名则拒绝执行并计入失败和拒绝次数。
别名并不能使模型看到所有旧证据：仍先按 I1 规则筛选工具返回，只保留后端映射以
解释历史引用。环境继续决定证据是否可用。

R 从真实 get_context、get_memories 和可信 user_events 重建：
**明确用户修正/澄清 > 最新已确认、未过期记忆 > context 回退**。
保留原 input.constraints，给最后一次成功 context 观察增添 effective_constraints、
effective_sources、effective_context_revision，并附固定系统说明要求规划使用解析值。
因此 R 是“显式解析值 + 来源标注 + 固定指令”的整体因素，不能单独归因于其中一句话。
消息中的原授权数据保持原样。

缺失读取不生成视图；撤回值 None 保持缺失并要求澄清；无有效记忆时回退公开 context；
非法枚举、重复 revision、坏日期、过时 revision 等使实验变 partial，不能静默默认器械。
解析器不接收 case_id、评分答案、expected action、隐藏环境约束或目录答案。
CPU oracle 可以读预期动作，但只在明确标为 scripted_contract 的演练中使用，GPU 路径不导入它。

这些是本轮事前门槛，不追溯替换 I1 的旧门槛。

新 A 是配对对照；历史 I1 view 仅用于复现核对。若新 A 相比历史有变化，披露全部
变化并保留四个新组的比较，不改门槛、不自动补跑、不把历史高分代替新 A。
始终报告 A→B、A→C、C→D、B→D 四条边及交互项，检查 N 是否只修 ID、R 是否只
修来源、组合是否引入副作用。不挑 B/C 得分救 D 的结论。

D 失败：按逐例证据决定是表示、来源、原环境引用或模型跟随问题；先离线分析，
不盲目扩训/加 seed。D 通过：只作为开发候选，再设计独立评估；仍不能宣布泛化
或直接部署，保留任务只在候选和评估协议另行冻结后使用。
