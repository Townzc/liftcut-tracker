## 研究问题与设计选择

E1模拟环境A/D各48/48不能证明模型能正确编排真实应用的批准、撤销和回执。应用使用周/天/动作结构，因此事前选择新`p1-model-tools-v1`工具schema，并明确是新的系统版本。固定[candidate-d-v1](../../research/liftcut-agent/reports/candidate-d-v1.json)中的父权重、基座和解码，不挑其他权重；不声称E1原样迁移成功。草稿由合成fixture供给，试验只验证编排，不验证模型自主制定训练处方。

[契约](../../research/p1-model/contract.ts)只开放`read_state`、`propose_draft`、`execute_plan`、`finish`。模型不能指定其他用户/run、改草稿、自行批准或撤销。真实UUID、Cookie和数据库URL留在可信本机端；模型使用稳定提案/批准/执行别名。执行键绑定run与提案，重建适配器不换业务意图。

一次输出须为一个工具调用，无自由文字断言。未知工具/参数/别名、不合法JSON、无回执的成功声明不会自动修复。评分字段不进入请求或工具反馈。原始请求/token/解析动作/实际结果/模型可见结果分别保留，外部事件标记`scripted_user`，不当真实用户试用。

## 固定24个已知开发工作流

[case源](../../research/p1-application/cases.ts)固定8流程×3约束组合，每个一次、顺序不变。它们已参与CPU开发，不能重贴未见验收标签。

| 流程 | 外部事件或故障 | 预期终态/真实提交 |
| --- | --- | --- |
| preview | 仅预览 | awaiting_approval / 0 |
| approve | 用户批准当前预览 | applied / 1 |
| no_reply | 发布后无用户答复 | awaiting_approval / 0 |
| decline | 用户拒绝 | declined / 0 |
| revoke | 批准后、执行前撤销 | revoked / 0 |
| context_update | 批准后改约束，重新预览 | awaiting_approval / 0 |
| lost_response | 实际提交后隐藏工具结果，查询原run | applied / 1 |
| resume | 检查点落盘、实际应用进程退出75后恢复 | applied / 1 |

preview/no_reply有相同可观察状态；resume/approve共享业务逻辑，区别在进程恢复。24不是独立样本。本轮丢结果是工具边界受控故障，重启是计划退出；P1另有真实浏览器网络丢包与提交后SIGKILL证据，不能混算。

## 冻结、执行和停止

[execution-v1](../../research/p1-model/execution-v1.json)固定189源；旧E1的146源原SHA不变。解码seed42、NF4 double quant/BF16、非量化层fp32、greedy、512输出/4096上下文，每case最多12请求，总上限288。失败不改schema/提示、不扩大预算或追加种子。

数据库只在本机loopback、使用全新空的合成开发库。一个长驻远端模型进程经单条SSH会话连接，只加载一次；3次计划应用重启复用该模型。两端独立预约防止换run-id重复启动。未知结果先检查已存在的进程和数据，不自动重连/再派发。

新开机消息后才生成真实授权文件，绑定原opening、最终受检commit和manifest SHA。配置模板的授权是false/null，不可执行。严格known_hosts/已信任指纹/getpass，无密码文件。只传小代码，实际验证缓存基座、父adapter、运行时和空闲GPU。

原opening+60分钟停止工作、+80分钟停止收集、+90分钟硬关机；启动超过10分钟即失败收尾。独立守护在模型加载前核对armed/原截止/实际进程参数，完成或失败提早关机，原硬截止保护保留。没有API、扩盘、训练、额外试验或重新开机。

每条原生请求与生成落盘后再返回应用。完整回执必须来自恢复器对真实父权重、全部24回合/native输入输出token、实际数据库备份恢复/受限读取/逐步新SQL回放的核验。候选研究失败仍可完整归档；partial不能变完整。回执上传/hash/原子发布/服务端消费分开记录，关机请求/返回/断连/平台状态分开记录。CPU回执明确不能被服务器当成模型ACK。
