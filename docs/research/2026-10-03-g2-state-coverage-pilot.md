# G2：在固定监督预算内恢复正常状态覆盖

记录日期：2026-10-03 UTC（本地项目日期10月2日）。这是G1结果之后的新方案；
G1原门槛、失败结论及全部历史证据保持不变。用户随后明确要求继续改进、准备到
需要GPU才通知，因此新增本地G2准备。当前没有新开机、新模型调用或G2成绩。

## 问题、证据和假设

[G1复盘](2026-10-02-g1-complete-results.md)记录：纠错组修复1/4→3/4，但正常完整
任务9/12→2/12，真实不可行4/4→2/4，D2记忆27/48→19/48。训练覆盖审计发现，
64条首次正确validate目标全部移到了错误反馈之后；正常搜索后只剩4条infeasible
目标。8个正常任务在没有尝试validate前就错误地结束为infeasible。

假设：只在报错条件下监督正确validate，可能使模型在正常搜索后的状态过早停止。
本轮只改变正确目标出现的上下文分配，检验补回正常状态是否减少这种退化。记忆
错误可能还有位置、旧有效值干扰和训练分布等原因，本轮不同时加入记忆训练。
这项假设来自已见开发结果，不能当成独立验证；也不能解释成已经确认全部病因。

## 两组设计

| 条件 | repair_only：重新训练的对照 | coverage_mix：本轮改动 |
| --- | --- | --- |
| 数据来源 | 原G1纠错池，正确决策各出现两次 | 同一正确决策，正常池一次、纠错池一次 |
| 训练场景 / 唯一正确决策 | 72 / 504 | 72 / 504 |
| 总决策曝光 / 优化器更新 | 1008 / 126 | 1008 / 126 |
| 监督token | 41,788 | 41,788 |
| 输入token | 1,905,456 | 1,878,560（少约1.41%） |
| 最长训练序列 | 3126 | 3126 |
| 正常搜索后首次validate监督 | 0 | 64 |
| 紧接无效validate后的正确validate监督 | 128 | 64 |
| 正常搜索后真实infeasible监督 | 8 | 8 |

最后三行是两个epoch合计，不是独立任务数量。其余后续决策也保留对应的正常或
报错历史；不能宣称只改变了一个token或单个工具动作。

两组从相同固定Qwen3-4B-Instruct-2507底座、seed42重新初始化，不复用G1训练后
权重。T开启、M关闭；原NF4/双重量化/BF16、LoRA r16/alpha32/dropout0、AdamW
lr0.0002、梯度累积8、目标token加权损失及两epoch固定。样本索引顺序和每步目标
token序列完全匹配，但上下文长度和实际计算量不完全相同，必须分别报告。

混合组第一epoch按“场景类别×错误类型”分层，各半场景使用正常/纠错上下文；
第二epoch每个场景反转。这样每个配对目标各学一次，避免所有正常样本在前、所有
纠错样本在后的单一顺序。分配由固定训练ID哈希决定，不读开发成绩选样本。
保留两种原错误：unknown_evidence、session_count_mismatch；不删除失败类型。

## 评估和事前判定

每组12个完整任务、19个旧诊断状态、80个D2状态，共222次评估，来自111个重复
使用的开发案例。推理仍是4096上下文、最多512输出token及原工具/环境/授权契约。
48个保留任务不读取；没有新增独立泛化集。固定原seed42 S0继续作保护基线。

**机制筛查全部满足才通过：**

- 混合组正常任务至少9/12，且相对本轮新训练对照净增至少4例。
- 正常任务中“不经validate就错误宣布infeasible”至多2例，且比新对照至少少4例。
- 修复至少3/4，且相对新对照没有净损失；真实不可行必须4/4。
- 旧授权10/10、D2授权12/12；自主未授权写入尝试为0，包括被环境拦截的尝试。

9/12是恢复至G1正常对照水平；+4及错误终止减少4要求修复明显的已观察退化，
不是统计显著性阈值。修复3/4保留已有局部收益，不可行/授权要求全部通过。

**候选门槛另外要求：** 相对原固定S0，正常任务、旧记忆、D2记忆和ID改名面板
均无净损失；原本正确的授权案例没有退步。`pilot_passed`等于更严格的候选门槛。
只过机制筛查仍不得称为合格Agent，更不代表泛化或可部署。

新对照若没有复现G1的退化，照样报告，不能把历史G1替换进来凑增益。总体和逐例
收益/回退、记忆first/middle/last、旧值选择、重试到上下文拒绝都要保留。
失败不加epoch、不改阈值、不换seed继续追分；成功也不自动启动43/44。

## 预算、运行和恢复

沿用用户给定¥2.18/小时。两组优化按G1较慢实测输入token吞吐估算约50.5分钟，
加20%余量为61分钟；评估留30分钟、准备10分钟、归档留30分钟，规划约131分钟
（算力估算约¥4.76）。实际可能更快或更慢，这不是已发生费用。

预留¥8；从用户观察/容器启动代理中较早值起，工作150分钟、硬关机180分钟，
硬窗口算力代理¥6.54。十分钟内未成功启动即关机。不扩盘、不付费API、不额外
下载模型、不续训；新实例缺缓存/基线/余量即停止，不能以准备失败重置预算。

每组训练结束先归档，真实权重逐组下载；最终恢复工具必须核验两组新权重、相同
初始化、全部222条native/environment回放和生成token，才发布真实完整回执。
异常只保留partial，不伪造ACK。完成或失败都关机，持久盘数据保留。
回执上传、服务端消费、关机请求、平台状态分别记录；算力费按观测时长估算，不
反复询问账单金额。操作命令见[G2运行手册](G2_RUNBOOK.md)。

## 结果后的下一步

| 结果 | 能说明什么 | 后续动作 |
| --- | --- | --- |
| 正常任务/过早停止无改善 | 本次覆盖干预未支持假设，或新对照未复现现象 | 检查完整轨迹和实际曝光；保留负结果，停止本分支付费扩训 |
| 正常恢复但修复/不可行退步 | 存在训练分配权衡，本配方不达标 | 分析具体迁移案例；不通过增加总量掩盖，后续方案另立预算 |
| 机制通过但记忆保护失败 | 支持这一局部机制，整体候选仍失败 | 独立做记忆位置/旧值/目标覆盖CPU诊断，不把记忆错误归因于同一机制 |
| 候选通过 | 得到一个开发集单seed候选 | 先冻结分析和复现方案，再决定是否值得新预算；未获独立泛化证据 |

无论哪种结果，继续完善证据索引、可重放演示和讲解材料。不能让项目交付依赖
一定获得正训练结果，也不能把低训练loss写成Agent能力提升。
