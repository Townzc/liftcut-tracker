# 下一轮：先复现状态覆盖效应，再选择候选

初稿写于 2026-09-29 四组窗口期间，已看到 S0/T 结果，M/TM 结果尚未全部得到。
这是下一轮的设计草稿，不是原实验的事前假设，也不是新 GPU 授权。执行前仍须
完成代码、CPU 准备、精确预算与 CI 冻结；当前实例只跑完原有四组并关机。

**完整结果后的更新：** 原窗口已完成、备份并进入关机流程。T 只在 S0→T 配对
通过筛选，M 两个配对均未通过；TM 在三个相关 pending 案例中新增被拦截写入，
因此不晋升为可靠性候选。保留四组重复的理由包括检验这一组合回退能否重现，
不是期待更多训练自动修复它。详见 [结果](2026-09-29-state-coverage-results.md)。

## 为什么先做稳定性

S0→T 已观察到读取后授权改善，同时有完整任务引用错误回退。一个初始化和采样
顺序不能说明这条取舍能否重复。若立刻改提示词、加 evidence 数据或上 DPO，就
无法区分原干预的稳定性与新改动。因此先保持原数据和协议，重复独立训练 seed。
所有比较保留每个案例的进退，不用训练 loss 或单个最高分挑 checkpoint。

## 拟定实验

在完整四组结果通过审计后，若至少一个原开发筛选因素通过，准备 seed43、44，
每个 seed 都重复 S0/T/M/TM。保留四组可观察因素是否相互抵消，避免根据 seed42
挑选一对漂亮比较。若完整审计否定筛选通过或发现数据/执行错误，则先修复并版本化，
不直接启动重复训练。

每组仍从同一固定基座开始；数据、正确目标、LoRA/量化/优化器、两轮训练和 final
checkpoint 规则不变。每个 seed 同时控制参数初始化与 epoch shuffle，组间共享
该 seed 的采样索引与目标 token。额外最长样本探针不更新参数；探针后重新设定
同一 seed。不能只改 manifest 的数字、继续使用固定 42 的初始化或采样器。

本轮版本的 runner 和准备文件继续保留，避免改动其 source hash 破坏历史复现。
新增有版本的重复实验入口、seed 目录、manifest 和回放报告。先在 CPU 检查：

- seed42 新准备路径与原样本顺序完全相同；43/44 可各自重建，且跨 seed 顺序不同。
- 同一 seed 内四组每一步监督序列完全一致；输入量差异继续报告。
- 仍只读取原 train/dev，48 个保留任务不打开；没有新增模板或提示改动。
- 训练、评测、归档、恢复回执都绑定 `(seed, arm)`，错误配对必须拒绝。
- 每个窗口独立预算与关机守护，部分失败保持部分结果，不补挑更好 seed。

## 怎样判断，不怎样挑结果

三个 seed 各自列出原四个配对、原筛选门槛、正常任务进退、主要记忆、读取后授权、
自主被拦截写入、格式/截断/上下文失败及成本。原 seed42 的结论不因后来均值改变。
同时列出跨 seed 的最小值、最大值和均值，但不把 3×同一批 dev 视为新独立任务。

下一轮的判断问题是“收益方向和代价是否重现”：两个新 seed 是否都在同一配对上
保持改善，是否出现新的授权或完整任务回退。若方向反转或只靠一个 seed 支撑，
优先报告不稳定，不继续追加 seed 直到得到好看的均值。最多按这个计划追加两次。
该规则用于筛选下一步工作，不构成显著性或泛化保证。

候选选择必须综合完整任务与授权/记忆行为；局部诊断通过但完整任务退化的组，
只能作为机制和修复研究对象，不能直接宣称更好的可部署 Agent。选定版本后再写
一次性保留评测方案和固定候选名单，冻结后才读取 48 个保留任务。无稳定候选时，
发布已有负结果并缩小主张，不反复用测试集找方向。

## 服务器与预算草案

继续复用 4090 24GB、模型和环境缓存，不需要 A800 或磁盘扩容。拟拆成两个窗口，
每窗四组对应一个 seed，完成立即备份核验和关机，不让实例等待下一轮决策。

| 项目 | 范围/上限 |
| --- | --- |
| 训练 | 2 seeds × 4 arms；每组 126 updates、41,788 监督 tokens |
| 新评测 | 8 × (12 完整任务 + 19 诊断) = 248 条；无保留测试 |
| 每窗 | 启动起至多 3 小时，实验截止 150 分钟，留 30 分钟备份 |
| 计算费代理 | 用户提供的 ¥2.18/小时 × 6 小时 = **¥13.08** |
| 规划预留 | **¥16**；未知存储费用另计，执行前核对实际订单价格 |
| 新权重归档 | 按前三组实测约 122 MB/组，八组约 980 MB；另保留原有实验 |
| 付费模型 API | 0；不使用 DeepSeek 余额 |

初稿依据的前三组优化循环约 23.4–23.9 分钟/组；这不包括环境准备、模型加载、评测、保存
重载和文件传输。正式冻结预算时，用本轮全部实际起止与备份时间重新估计。如果
合理余量无法装入三小时，应拆分窗口或减少本次范围并重新说明，不能让守护时间
从启动任务时重新计算，也不能为凑分数默默延长租期。

完整四组实测优化循环为 23.35–23.91 分钟/组；整个窗口从启动代理到关机后连接
检查为 130.69 分钟，计算费代理约 ¥4.75。实际转移每份约 122 MB 归档约 1–4 分钟，
前三份与后续计算重叠。这支持继续评估每个 seed 一个三小时窗口，但不保证换实例
后的网络/显卡吞吐相同；执行前仍需将准备和备份余量写入新 manifest。

## 完成稳定性之后

1. 若授权改善稳定但 `unknown_evidence` 回退也重现，单独设计 evidence grounding
   的训练数据对照：有效记录 ID、block ID、不存在 ID 的边界，以及验证失败后修正
   引用与真正不可行的区别。仅操作训练 split，保持协议不变，修复后的评测另版本化。
2. 若主要记忆已接近当前诊断上限，新增开发诊断检查中间位置、更多排列、来源值
   交换和更长记录列表。明确这些是看到本轮结果后构造的诊断，不能冒充独立测试。
3. 稳定候选冻结后，执行保留评测及 [外部迁移准备](2026-09-29-external-transfer-preflight.md)。
   外部数据来源、接口和评分器另行核对，不把内部工具调用协议强行套到外部基准。
4. 只有这些证据支持更进一步优化时，才考虑同状态分叉审计的 DPO 或在线 RL；不以
   方法名称替代问题定位、对照和独立验证。
