## 模型与试跑目标

候选：`Qwen/Qwen3-4B-Instruct-2507`，固定 revision
`cdbee75f17c01a7cc42f958dc650907174af0554`。
该模型已经过指令训练；项目对照组称为“未做本项目适配的模型”，避免把它描述成
未经后训练的预训练基座。[官方模型说明](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)

制定原方案时已完成：真实 tokenizer 的 59 个决策检查，最长 2,973 tokens，4,096 长度内无截断；
2,766 个助手目标 tokens 与 104,177 个上下文 tokens 分开标注。只下载了 tokenizer、
配置和许可证，没有下载权重。后续权重下载、20 步训练和 adapter 重载实测见
[执行报告](2026-09-28-gpu-pilot.md)。当前样本来自公开开发场景，仅用于验证流水线。

试跑要回答四个问题：模型能否按本项目工具 schema 输出；多轮工具消息是否正确往返；
4090 的峰值显存和实际吞吐是多少；一次短训练与保存/加载 adapter 是否保持正确的
loss mask。短训练只用于检查流程，不报告能力提升。

## 配置草案与时间盒

| 项目 | 试跑设置 |
| --- | --- |
| GPU | 1 × RTX 4090，24GB 显存 |
| CPU / 主存 | 目标至少 8 vCPU、32GB；下单时核实实例分配 |
| 可用磁盘 | 原目标 60GB；实际实例 50GB，先验证剩余空间，仅下载 4B 权重及少量 adapter，不自动扩容 |
| 系统 | 原目标 Python 3.11；实际镜像 Python 3.12.3 / Torch 2.8.0+cu128，独立 venv 复用 Torch，重跑跨版本审计 |
| 上下文 | 4,096，超过时明确失败，不静默截断 |
| 首次推理 | 加载同一固定 revision，验证 native tool schema、call ID 和服务解析器 |
| 训练兼容试跑 | 4-bit NF4 QLoRA、BF16 计算、LoRA r=16/alpha=32、micro-batch=1、梯度累积=8、gradient checkpointing；均为待验证配置 |
| 训练范围 | 最多 20 optimizer steps，仅测 loss、显存、吞吐和 adapter 重载；不把 smoke 数据评测当作泛化 |
| 进程上限 | 单阶段设置超时；整个实例最多 4 小时，到点终止并关机 |

建议时间盒：环境/下载最多 1 小时；未适配模型工具兼容与开发回放 1 小时；短训练和
adapter 重载 1 小时；结果导出及缓冲 1 小时。它们是停止边界，不是已测得的耗时。
环境在首小时内装不通、反复 OOM、目标 token 被错误屏蔽或出现 NaN，就保存诊断并停机。
实际训练时长须根据此次测得的 tokens/s 再估算。

## 开机、检查点和停机流程

1. **开机前**：数据清单、模型 revision、依赖锁定、运行命令、订单截图/单价和磁盘收费
   均已准备；先配置 4 小时停机保护，确认它作用于正确实例。付费任务开始前测试停机路径。
2. **运行中**：记录实例 ID、开始时间、每阶段耗时、GPU 峰值显存和 tokens/s；日志写入
   持久文件。每 5 个 optimizer steps 保存小型 adapter/训练状态；保存前检查磁盘空间。
3. **成功或失败退出**：退出处理都触发实例关机，不仅结束 Python 进程。平台文档支持
   用 `/usr/bin/shutdown` 在程序结束后关机；具体使用前验证实例行为。
   [官方自动关机说明](https://api.autodl.com/docs/save_money/)
4. **确认结束**：查看平台实例状态与计费结束时间，下载日志、adapter、配置、输入哈希和
   结果，验证文件可读。不能把进程退出等同于 GPU 计费停止。
5. **清理收费存储**：确认备份后再处理不再需要的付费磁盘。平台说明付费扩容盘在实例
   关机后仍可能计费，须单独检查。[官方计费规则](https://www.autodl.com/docs/price/)

正式 SFT 仍需独立标签审查、按 family/persona 分组的评测冻结、足量可执行训练轨迹、
matched-token 消融和模型服务的实际验证。本方案通过后才提交后续训练的时长与预算，
本轮使用维护者已开启的实例，不另行创建或购买 GPU 实例。
