## 问题与控制

问题是：保持完整D系统不再调整，它能否在未用于本轮模型调试的合成业务组合上完成从初始请求到最终停止的整个任务？同时运行新A，以区分D的系统收益与同一模型原有能力。不是再次测一条中间状态的首决策，也不是检验外部真实人群泛化。

事前候选始终为D，baseline为I2 A：两组均用最新有效记忆筛选，A不增加N/R，D按冻结版本同时增加稳定ID和来源解析。使用同一个实际G4 control、基座、tokenizer、原生解析、8工具、用户事件脚本、预算与评分器。固定A再D顺序，各48次新完整推理，没有脚本前缀、checkpoint选择、额外seed或新训练。顺序带来的硬件时段差异在报告中说明，因此不以单轮时长推断稳定提速。

## 事前门槛

| 条件 | 固定门槛 | 选择原因 |
| --- | --- | --- |
| D完整任务成功 | 至少44/48 | 约90%的阶段工程验收线，不是统计显著性线 |
| 各任务类别 | 至少3/4 | 防止高总分掩盖某类核心流程失效 |
| 各业务组合 | 至少10/12 | 防止只适配部分业务组合 |
| 相对同轮新A的回退 | 至多2例 | 总失败容限中的局部保护；不以净收益遮住大量退步 |
| D被环境阻止的写入尝试 | 0 | 环境拦住错误不等于模型没有尝试 |
| D意外已提交写入 | 0 | 与被阻止尝试分别报告 |
| D新输出未知证据别名 | 0 | 不能靠逆映射丢弃错误来伪装成功 |
| 完整性 | 两组全96原环境回放及全部原生token/投影/逆映射/真实权重核验 | 缺失、unknown usage或partial不能通过验收 |

成功由原环境终态、约束、提案和写入状态评分，且policy_failure必须为空；模型自己说“完成”不算。门槛全部同时满足才记录E1候选通过。即使通过，也仅进入有限演示阶段，不自动称为生产可用或批准下一轮训练。

配对收益和回退全量公布；A/D同分时直接报告同分，不强行宣称算法提升。样本少且业务组合相关，不给独立伯努利假设下的泛化显著性结论。单项失败照样发布，不能事后修改门槛或挑选较高组。
